# AISTING v16 Windows 실기기 검증 인계 — 아직 미실행

**실제 사용자 PC에서만 검증할 수 있는 항목입니다.** 원본 사용자 설정·기억 DB·100단계 기록을 절대로 실험 대상으로 직접 수정하지 않습니다. 외부 프로그램/모델 설치·다운로드, 음성 재생, 방송 송출·공지·로그인은 별도 사용자 승인 없이는 하지 않습니다.

1. 기존 전체 AISTING 소스가 있는 경우 원본을 그대로 두고, `prepare_local_source_copy.py`의 검토 모드로 파일 목록과 SHA를 확인합니다. 사용자가 승인한 경우에만 `--copy`로 **별도 로컬 사본**을 만듭니다. 이 사본에 `apply_to_existing_aisting.py` 검토 모드를 실행한 뒤 승인 시에만 `--apply`합니다. `audit_local_patch_preservation.py`가 기존 파일/폴더 변경 없음(허용된 패치 파일 제외)을 표시해야 합격입니다.
2. 원본의 실제 사용자 설정 파일이 아닌 **테스트용 별도 Windows 사용자 프로필/격리된 로컬 설정 경로**에서 실행합니다. (기존 `offline_settings.settings_file()`은 기본적으로 `%LOCALAPPDATA%\\AISTING\\settings.json`을 사용합니다.) 운영 중인 원본 설정을 실험용으로 덮어쓰지 않습니다.
3. 방송 플랫폼/콘텐츠를 한 번 저장하고, **내 캐릭터**에서 이름·말투·성격을 편집한 뒤 전용 **캐릭터 확정·저장**을 누릅니다. 합격: 설정을 다시 읽었을 때 확정한 캐릭터가 있고 기존 플랫폼·콘텐츠가 유지됩니다. 기존 설정 파일이 있었다면 `settings.json.before-character-*.bak` 백업이 존재하고 원본 바이트가 일치해야 합니다.
4. 프로그램 종료 후 재실행합니다. 합격: 확정한 캐릭터가 자동 복원됩니다. 그다음 캐릭터 초안을 바꾸되 **확정 저장을 누르지 않고** 일반 **방송 설정 저장**을 실행합니다. 합격: 다시 시작해도 확정 캐릭터가 유지되며 초안은 실제 AI/방송 설정에 적용되지 않습니다.
5. 두 개의 프로그램 창을 동시에 열어 같은 설정을 저장하는 시험은 하지 않습니다. v16은 파일 변경을 감지하지만 다중 프로세스 원자적 잠금은 구현하지 않았습니다.
6. 공식 Open-LLM-VTuber 서버가 이미 준비된 경우에는 승인 후 실제 AI 대화·한국어 TTS·Live2D를 **별도 검증**합니다. 이 문서의 캐릭터 저장 검사만으로 AI·음성·아바타·OBS·실방송 완료로 판정하지 않습니다.

**오류 수집:** 실행 단계/Windows 버전/Python 버전, 실패 메시지, 종료 코드, 테스트용 `settings.json` 및 백업 파일의 SHA-256·크기·수정시각(내용 제외), 개인정보를 지운 콘솔 로그를 기록합니다. API 키, 캐릭터 설정 원문, 사용자 기억 데이터, 음성 녹음, OBS 비밀번호를 공유하지 않습니다.
