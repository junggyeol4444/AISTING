# AISTING v24 Windows 실기기 검증 — 나중에 운영자가 수행할 절차

현재 사용자 요청대로 **실기기 검증은 보류**합니다. 아래는 이후 필요한 확인 절차와 오류 수집 방법이며, 자동 실행하지 않습니다.

1. 기존 AISTING 원본은 **복제본**으로만 검증. 프로그램의 현재 설정·기억·캐릭터 저장값·100단계 기록 해시 백업 및 별도 보관.
2. 검증된 기존 소스 사본에서 `apply_to_existing_aisting.py --check`로 정합성 확인 후, 변경 사항을 검토하고 사용자 승인하에 별도로 `--apply`. 복제본 원본 `.bak`과 보존 감사 결과 기록.
3. 기존 AISTING Windows EXE 또는 기존 프로그램을 실행하고 `방송인 홈 > 1단계 기존 Live2D 모델 선택`에 진입. 사전에 설치된 공식 Open-LLM-VTuber 폴더를 지정하고 `model_dict.json` 항목과 실제 파일 존재를 확인.
4. 사용자가 기존 모델을 선택하고 **명시적으로 승인**하면 `conf.yaml` 파일 내 `character_config.live2d_model_name`만 변경되며, 동일 모델은 변경 없음. 원본의 다른 설정, 캐릭터, TTS, 사용자 데이터가 보존되고 `.bak`이 생겼는지 확인.
5. 승인 취소, 필수 모델 파일 누락, 파일 변경 충돌 시 `conf.yaml`은 수정되지 않는 것이 합격 기준.
6. 나중에 공식 AI 코어를 별도 승인하여 실행한 뒤 WebSocket 초기화 `model_name/model_url`을 확인. **모델 정보 수신은 실제 Live2D 렌더링 증거가 아님**. Live2D 화면에서 실제 움직임 및 음성 연동을 직접 확인해야 1단계 일부 실기기 판정 가능.
7. 모델이 보이지 않거나 설정이 변경된 경우, 오디오·사용자 비밀값·전체 설정 파일을 보내지 말고 시간, 오류 문구, AISTING 버전, 해당 공식 모델 이름, 미검증 단계, 필요한 부분만 비식별화한 로그 수집. 원본 비밀·채팅 기록 유출 금지.
