# AISTING v20 — Windows PC 검증 인계 (아직 실행하지 않음)

이 절차는 사용자 PC에서만 가능한 **추후 실기기 검증**입니다. 원본과 `%LOCALAPPDATA%\AISTING\settings.json` 및 기억·100단계 기록은 별도 백업하고, 사용자 동의 전 실제 방송/계정 연결/모델 설치·학습을 하지 않습니다. **원본이 아니라 검증된 로컬 복제본에서만** 패치를 적용합니다. 전체 원본 SHA와 보존 검사는 v19 문서를 따릅니다.

1. 복제된 AISTING에서 캐릭터 이름·말투·성격을 전용 **캐릭터 확정·저장** 버튼으로 확정하고 앱을 종료·재시작합니다. **합격:** 디스크의 확정 캐릭터가 방송인 홈과 실제 사용 캐릭터에 동일하게 복원되고 미확정 초안은 적용되지 않습니다.
2. 두 개의 복제 앱 창을 열고 A 창의 캐릭터를 확정한 뒤, 오래 열린 B 창에서 **저장된 캐릭터 정보 새로 고침**을 누릅니다. **합격:** B의 표시가 A의 디스크 확정값과 일치하며 B의 저장하지 않은 방송 설정 편집값은 보존됩니다.
3. B 창에서 공식 `conf.yaml` 비교를 수행합니다. **합격:** 저장하지 않은 캐릭터 초안이 아닌 현재 디스크 확정값으로 비교하고, 다른 창에서 확정한 값이 반영됩니다. 실제 공식 프로그램의 설정 파일을 읽기만 하므로 서버 실행 증거는 아닙니다.
4. 별도 승인 후 **공식 캐릭터 설정 적용** 확인 창을 연 상태에서 A 창의 확정 캐릭터를 변경하고 B 창에서 확인을 누릅니다. **합격:** B는 캐릭터 변경 충돌 오류를 보여 주고 `conf.yaml`을 덮어쓰지 않습니다. 원본 파일 SHA-256과 백업 생성 여부로 확인합니다. 이 검증은 공식 설정 파일에 쓰기가 가능한 동작이므로 사본·백업 준비 및 사용자 승인 후에만 수행합니다.
5. **설정 사본에서만** `settings.json` 누락 또는 JSON 손상을 시험합니다. **합격:** 확정 캐릭터를 기본값으로 조용히 대체하지 않고 오류를 표시하며 손상 파일을 수정하지 않습니다.
6. 오류 수집: Windows/앱/Python 버전, 버튼, 시각, 재현 순서, 화면 상태 문구, 비밀정보를 제거한 예외 로그와 변경 전후 파일 SHA-256. 비밀번호·토큰·목소리·사용자 JSON 원문은 보내지 않습니다.

실제 LLM 응답, 한국어 TTS/GPT-SoVITS, Live2D·VRM, 실제 플랫폼 채팅, OBS 송출, 스케줄러, 공지는 각각 별도의 승인 및 실제 성공 증거가 있어야 하며 이 테스트만으로 완료 판정할 수 없습니다.
