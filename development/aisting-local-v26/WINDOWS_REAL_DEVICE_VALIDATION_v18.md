# AISTING v18 — 사용자 Windows PC 전용 검증 절차 (미실행)

**주의:** 이 문서는 검증 인계입니다. 지금까지 Windows PC에서 실행하거나 실제 방송을 검증한 결과가 아닙니다. 기존 프로그램과 사용자 설정을 직접 덮어쓰지 마세요.

1. 기존 AISTING 원본 소스, `%LOCALAPPDATA%\AISTING\settings.json`, 기존 기억 데이터, `config/roadmap.json`, `docs/ORIGINAL_PLAN.txt`, 100단계 기록을 각각 별도 백업하고 백업 위치를 기록합니다. 비밀번호·토큰은 공유하지 마세요.
2. 전체 원본 소스가 준비되면 `prepare_local_source_copy.py`로 별도 사본을 만들고, `apply_to_existing_aisting.py --check`에서 `desktop.py` Git blob SHA `a5df12a74a27a5a50657da9c968253859b98b8ed` 및 코드 앵커를 확인합니다. **원본에 `--apply` 금지.** 검증된 별도 사본에만 명시적으로 적용한 후 `audit_local_patch_preservation.py`를 실행합니다. 패치/감사가 실패하면 원본은 그대로 두고 중단합니다.
3. 사용자 동의하에 복제된 설정과 앱을 실행해 캐릭터 이름·말투·성격을 **전용 캐릭터 확정 저장**으로 저장한 뒤 앱을 종료·재시작합니다. **합격:** 동일 캐릭터가 자동 복원되고, 일반 방송 설정 저장만으로 미확정 초안이 적용되지 않습니다.
4. 두 앱 창에서 동시에 설정을 저장해 충돌을 재현합니다. **합격:** 한 창이 저장 중이면 다른 창은 명확한 저장 충돌 오류를 표시하고 파일을 덮어쓰지 않습니다. 완료 후 잠금 파일 `.settings.json.aisting-write.lock`이 남아 있어도 정상입니다. 두 창이 서로 다른 시점에 변경했다면 기존 비캐릭터 설정은 최신 상태를 보존하거나 충돌 오류로 거부해야 합니다. **실제 Windows 잠금은 이 단계 전까지 미검증입니다.**
5. `settings.json.before-character-*.bak` 및 `settings.json.before-broadcast-*.bak`를 확인합니다. **합격:** 백업이 변경 전 파일과 바이트 단위로 같고, 기존 기억/100단계 기록은 패치 전 해시와 일치합니다. 사용자 데이터는 외부로 보내지 마세요.
6. 오류 수집: 앱 버전, Windows 버전, Python 버전, 조작한 버튼, 재현 순서, 시각, 오류 문구, 예외 유형, **민감정보를 가린** traceback을 보관합니다. 설정 JSON, 음성 원본, 채팅, 계정 토큰, 개인 파일은 첨부하지 마세요. SHA-256은 파일 내용 공개 없이 비교할 수 있습니다.
7. 실제 LLM 응답·한국어 TTS/GPT-SoVITS·Live2D/VRM·OBS·실제 플랫폼 채팅·스케줄러는 **각 기능별 별도 실기기/라이브 승인과 성공 증거가 필요**합니다. v18 로컬 검사는 이를 대신하지 않습니다. 승인 전에는 설치, 모델 학습, 마이크/스피커, 방송 송출, 계정 연결, 공지를 수행하지 않습니다.
