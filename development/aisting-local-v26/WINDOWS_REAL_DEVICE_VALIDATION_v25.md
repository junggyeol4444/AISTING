# AISTING v25 Windows 실제 기기 확인 절차 — 개발 중, 지금 실행할 필요 없음

이 안내는 나중에 사용자가 직접 진행할 수 있는 검증 절차이며, **이번 회차에 검증했다는 기록이 아님**.

1. **기존 설치본을 백업**하고 기획안 및 사용자 설정/기억/100단계 기록의 SHA-256을 보존한다. 공식 Open-LLM-VTuber는 사용자가 설치와 모델·서비스 설정을 별도 승인한 후 이미 준비된 복사본이어야 한다. 사전 검사 후에만 `AISTING` 개발 수정본을 사용한다.
2. AISTING의 `공식 프로그램 폴더`에서 기존 공식 프로젝트를 지정한다. `frontend/index.html`, `run_server.py`, `pyproject.toml`, `conf.yaml` 존재를 확인한다. 누락되면 프로그램은 다운로드 없이 실패를 표시해야 한다.
3. 이미 **안전하게 실행 중인** 로컬 공식 서버가 있을 때에만 `공식 Live2D 화면 열기 (별도 브라우저 · 승인 필요)` 버튼을 누른다. 승인 취소 시 네트워크 요청/브라우저 실행이 없어야 한다.
4. 서버 HTTP가 302/404/JSON만 반환하면 프로그램이 브라우저를 열지 않아야 한다. HTTP 200/HTML 확인 시 이미 설치된 공식 프런트엔드의 `http://127.0.0.1:12393/` 주소로만 브라우저가 열려야 한다.
5. **실제 기능 검증:** 해당 공식 프런트엔드에서 사용자가 승인한 후, 실제 등록한 Live2D 모델이 화면에 렌더링되는지, 승인된 실제 LLM 질문이 자연스러운 한국어 응답을 만드는지, 실제 음성이 재생되고 표정·입 모양이 음성과 맞는지 사용자가 직접 판단한다. AISTING 텍스트 대화 창과 공식 브라우저는 별도 세션일 수 있으므로 같은 대화를 공유한다고 간주하지 않는다.
6. 음질·캐릭터·자연스러움의 합격 기준은 **사용자가 판단한다**. 자동 판정/인위적 지연/채팅 선별 없음. 사용자 승인 없는 송출·게시·녹음 금지.

**오류 수집:** 실행 전·후 `AISTING` 상태 문구, 정확한 시각, 서버 종료 코드, 공식 서버 로그, 브라우저 개발자 콘솔 오류, 모델 URL/존재여부, OBS를 사용하지 않았다는 상태를 수집한다. 인증 토큰/개인정보/캐릭터 비공개 데이터/유료 API 키는 공유 전 지운다. 오류가 발생하더라도 설치·브라우저·서버 다운로드를 강행하지 않는다.
