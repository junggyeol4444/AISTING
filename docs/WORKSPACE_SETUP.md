# 16단계 준비 — 개발용 폴더와 작업 공간 구성

이번 기능은 **사용자가 직접 선택한 상위 폴더** 안에 `AISTING_Workspace` 작업 폴더를 만들 수 있도록 준비한 것입니다. 프로그램이 실행되거나 해당 탭이 열릴 때는 작업 폴더를 생성하거나 PC 파일을 검색하지 않습니다. 이 대화의 개발 ZIP 생성 작업은 사용자 PC와 별개인 실행 환경에서 수행했습니다.

## 사용자 선택 절차

1. 프로그램의 **개발 작업 공간** 탭에서 기존 상위 폴더를 직접 입력하거나 **폴더 선택**을 누릅니다.
2. **작업 공간 계획 미리보기**를 누르면 생성될 위치와 내부 폴더 목록만 표시합니다. 파일 읽기·쓰기는 하지 않습니다.
3. 사용자가 **작업 공간 생성 (수동)**을 누르고 확인 대화상자에서 동의한 경우에만 폴더를 만듭니다. 취소하면 아무것도 변경하지 않습니다.

구성은 `source/`(개발 소스 보관 공간), `backups/`(향후 백업 공간), `exports/`(향후 결과물 공간), `logs/`(향후 로컬 로그 공간), `notes/`(운영자 메모 공간), `workspace_manifest.json`(AISTING 작업 공간 식별 파일)입니다. **폴더만 만들며 소스 파일 복사·설치·백업은 자동으로 수행하지 않습니다.** `backups` 폴더를 만들었다고 복구 가능성이 검증되는 것은 아닙니다.

## 기존 파일 보호

- 지정한 상위 폴더는 이미 존재해야 합니다. 경로를 자동 생성하거나 사용자 홈 폴더를 추측하지 않습니다.
- 동명 작업 폴더가 비어 있지 않고 유효한 AISTING 식별 파일이 없다면 중단합니다. 다른 프로그램의 데이터를 덮어쓰지 않습니다.
- 식별 파일이 있는 기존 AISTING 작업 공간은 구조를 확인한 후 누락된 하위 폴더만 보충할 수 있습니다. 기존 사용자 파일과 식별 파일은 덮어쓰지 않습니다.
- 파일과 디렉터리 충돌, 식별 파일 변조, 심볼릭 링크/정션 경로는 중단합니다. 실패 시 자동 삭제나 강제 복구를 하지 않습니다.
- 예상치 못한 디스크 오류로 생성이 중간에 멈추면 일부 폴더만 남을 수 있습니다. 안전을 위해 임의 삭제하지 않으므로 사용자가 직접 상태를 확인해야 합니다.

## 승인·검증 경계

10단계 개발 기준 최종 승인, 11~14단계 실제 PC 검토, 15단계 프로그램 설치 승인, 16단계 사용자 PC 작업 공간 실제 구성 및 확인은 별개입니다. 이번 코드는 16단계 기능을 **준비**한 것이며 사용자 PC에 작업 폴더를 실제로 생성하거나 승인한 것이 아닙니다. 공식 완료 단계는 9/100을 유지합니다.
