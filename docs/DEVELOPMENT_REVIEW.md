# 10단계 · 전체 개발 기준 최종 검토 — 오프라인 v11

AISTING 프로젝트의 **전체 개발 기준을 사용자 PC 내부에서 검토할 수 있는 기능**을 구현했습니다.

## 10단계의 정확한 의미

- 001~009의 개발 기준은 현재 코드·테스트 단계에서 검증되었습니다.
- 010 '전체 개발 기준 최종 승인'은 개발자가 임의로 대신 승인하는 과정이 아닙니다.
- 이번 v11은 **검토 항목을 표시하고, 운영자가 PC 화면에서 명시적으로 확인할 때만 로컬 승인 기록을 남길 수 있는 구현**입니다.
- ZIP의 `config/roadmap.json` 10단계는 여전히 `pending`으로 유지합니다. 작성자나 빌드 도구가 승인하지 않습니다.
- 다음의 011 PC 운영체제, 012 CPU/RAM/GPU 검사 등은 **사용자의 PC가 켜지고 요청/권한이 주어지기 전까지 자동 조회하지 않습니다.**

## Windows 프로그램에서의 사용법

1. **개발 기준 검토** 탭을 열어도 네트워크, 파일 쓰기, 계정 연결은 시작되지 않습니다.
2. **개발 기준 검사 (PC 내부 파일만 읽기)** 버튼을 눌러 번들에 포함된 `config/requirements.json`, `config/roadmap.json`과 마지막으로 저장된 PC 설정을 검사합니다.
3. 검토 목록은 모든 메시지 순서대로 답하기·플랫폼 선택형·로컬 무료 실행·사전 동의·예약 차단 등의 기준을 포함합니다. 검토 실패 또는 미저장 설정 변경이 있으면 승인이 차단됩니다.
4. 운영자가 내용을 직접 검토했다면 체크박스 선택 → **개발 기준 최종 승인 기록 (수동)** → 재확인 대화상자 '예'를 선택할 때에만 `development_criteria_approval.json`을 PC의 AISTING 데이터 폴더에 기록합니다.
5. **내 PC 승인 기록 취소**를 누르고 확인하면 해당 승인 기록 **하나만 삭제**합니다. 캐릭터 설정·대화 DB·로드맵 원본은 변경하지 않습니다.

## 승인 기록 유효성

- 로컬 JSON 기록에 확인 시각(UTC)과 JSON 문서/저장된 설정에 대한 SHA-256 **내용 비교용 해시**를 기록합니다.
- 다른 설정을 저장하거나 기획 기준 문서가 수정되면 과거 기록이 현재 기준과 일치하지 않으므로 재검토가 필요합니다.
- 파일 손상·분실도 자동 승인으로 간주하지 않습니다.
- **SHA-256은 신원 인증/전자서명/위변조 방지 장치가 아닙니다.** 동일 PC 파일을 다른 프로그램에서 임의로 수정하는 사용자를 막을 수 없습니다.
- 이 승인 기록은 **개발 설계 기준만** 적용합니다. Windows 프로그램 설치, 비용 결제, OBS/플랫폼 송출, 계정 로그인, PC 사양 수집, 음성 녹음·복제, 예약 작업 실행은 **별도 승인**이 필요합니다.

## 실제 Windows EXE 빌드에서의 자료 경로

Windows의 `build_exe_windows.bat`는 기존 PyInstaller가 PC에 이미 있을 때에만 수동 실행할 수 있습니다. 해당 배치 파일에 `--add-data "config;config" --add-data "docs;docs"`를 추가하여 **EXE 내부 로컬 번들**에 검토할 기획 기준 문서와 로드맵을 함께 포함하도록 보완했습니다. 프로그램은 런타임 `sys._MEIPASS`에서 번들 자료를 읽습니다. GitHub 또는 인터넷에서 내려받지 않습니다.

이 대화의 Linux 가상 GUI 테스트와 Python 단위 테스트로 동작을 확인했지만, **Windows 실기기에서 PyInstaller 빌드한 EXE의 실행 결과는 아직 확인하지 않았습니다.**
