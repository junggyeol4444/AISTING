# v68 / 원본 067 — 시청자와 대화 맥락 연결 (수동 오프라인 모의)

## 원본 계획 및 이전 구현 검토

`docs/ORIGINAL_PLAN.txt` 1부의 원칙은 **모든 채팅에 반응, 기본 채팅 선별/인위적 지연 없음, 자연스러움은 운영자 판단**입니다. `docs/ROADMAP_100.md`와 `config/roadmap.json`의 원본 067은 `시청자와 대화 맥락 연결`입니다. 기존 026의 모의 맥락 전달, 029의 저장 응답 연속성 시험과 062 수신함, 063 순서, 065 모의 응답, 066 응답 시간 관찰을 검토했습니다. 기존 065는 **최근 성공 응답 8건을 전체 시청자 구분 없이** 모의 포트에 전달합니다. 원본 067의 시청자별 연결을 기존 065 경로에 선택적으로 추가합니다. 원본 068의 다중 시청자 대화 운영·실시간성·동시 처리 기능을 완료했다고 주장하지 않습니다.

## 실제 변경

- `src/ai_broadcaster/offline_chat_reactions.py`: `enable_viewer_context()`는 **운영자 명시적 호출** 시 기존 모의 응답 세션의 맥락 정책을 활성화합니다. 첫 응답 후 변경은 차단하여 하나의 세션에서 정책이 뒤섞이지 않게 합니다. 활성화된 경우 `reply_next()`가 **동일 `(platform, sender)`의 이전 성공 응답 최대 8건**을 원래 `MockCoreReplyPort.generate(CoreInput, history)`에 전달합니다. 기존 065/066의 FIFO·중복 메시지 보존·오류 중단/수동 재개·수동 측정 경로를 그대로 재사용합니다. 미응답·실패 건은 맥락에 넣지 않습니다. 기본 정책은 이전과 같으며 **자동으로 활성화되지 않습니다**.
- `src/ai_broadcaster/offline_viewer_context.py`: 기존 065 세션의 상태를 읽는 `OfflineViewerContext`와 `ViewerContextReport`를 추가합니다. 다음 동기화 대기 메시지에 전달될 시청자별 이전 성공 응답 순번을 읽기 전용으로 미리 볼 수 있습니다. 기존 수신함/순서 기록/설정/SQLite에 쓰지 않습니다.
- `시청자 대화 맥락 연결` Tk 탭: `시청자별 맥락 연결 활성화` 버튼과 `다음 대기 채팅 맥락 새로 보기` 버튼을 제공합니다. 모의 응답 자체는 기존 `전체 채팅 모의 응답` 또는 `채팅 무지연 모의 시험` 탭에서 **운영자 수동**으로 수행합니다.

## 시험 절차

1. 방송 설정에서 테스트 플랫폼을 선택하고 `플랫폼 채팅 연결 모의`에서 수동 가상 연결합니다.
2. `채팅 수신 모의`에서 직접 가상 닉네임과 메시지를 입력하고, `메시지 순서 관리`에서 수동 동기화합니다.
3. **첫 모의 응답 전에** `시청자 대화 맥락 연결` 탭에서 시청자별 맥락을 활성화합니다. 이미 답변을 시작했다면 기존 응답을 섞지 않도록 활성화를 차단합니다.
4. `전체 채팅 모의 응답`에서 수동 동기화 후 한 건씩 응답하거나 최대 50건을 처리합니다. `시청자 대화 맥락 연결` 탭에서 다음 대기 채팅의 맥락을 수동으로 다시 확인합니다.

## 제한과 승인

- `(platform, sender)`는 사용자가 직접 입력한 **가상 닉네임 문자열**입니다. 실제 플랫폼 사용자 ID나 계정 인증이 아니며 닉네임 변경/동명이인/계정 연동을 해결하지 않습니다.
- 이 단계는 **이미 성공한 모의 답변의 맥락 전달**만 보장합니다. 실제 AI의 의미 이해, 시청자 장기 기억, 실시간 다중 채팅, 음성/아바타/OBS 송출을 검증하지 않습니다.
- 네트워크·GitHub·외부 API·프로세스 실행·SQLite·파일 저장·사용자 PC 접근 없음. 테스트는 Linux Xvfb 가상 화면이며 Windows 실기기/EXE 검증은 보류합니다.
- 원본 067과 사용자 승인 010의 체크박스 및 JSON `pending`은 유지합니다. **코드 개발 도달 범위 67/100**과 실제 운영 승인 상태를 구분합니다.
