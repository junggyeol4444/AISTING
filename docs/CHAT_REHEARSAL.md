# Windows EXE 시청자 채팅 처리 연습 (실방송 연결 전 단계)

AISTING.exe의 **시청자 채팅 연습** 탭에서 운영자가 가짜 시청자 대화를 여러 줄 붙여 넣어
AI 방송인의 기본 원칙인 **모든 채팅 순서대로 반응**을 PC에서 시험할 수 있다.

## 입력 방법
- 한 줄에 '닉네임: 시청자 메시지' 형식, 빈 줄만 무시.
- 메시지의 콜론(:)은 첫 구분자 이후 그대로 보존.
- 같은 사람이 같은 채팅을 여러 번 올려도 **모두 독립 메시지**로 저장하고 각각 답변.
- 한 번에 최대 500줄. 초과나 잘못된 줄은 일부만 받지 않고 **전체 입력을 거부**하며
  적절히 나눠 다시 입력하도록 명시. 기존 대기열은 변경되지 않음.
- 여러 번 추가해도 **대기열(FIFO)** 순서대로 쌓임.
- 사용자가 '모두 답변'을 눌러야만 처리 시작. 의도적 지연/메시지 선택/분류 없음.
- **현재 답변 후 중지**는 이미 수행 중인 응답만 완료하고 남은 대기열을 그대로 보관.
- 로컬 AI 실패 시 실패한 메시지는 대기열에 남고, '모두 답변'으로 같은 설정으로 재시도.
- '새 연습'은 미응답 채팅이 있으면 운영자가 명시적으로 확인해야 지움.

## 답변 방식
- 기본 **설치 없는 모의 응답**: 실제 LLM이 아닌 고정 시험 문구. 무료/완전 오프라인.
- 선택 **무료 로컬 AI (Ollama)**: 이미 사용자 PC에서 실행 중인 모델명을 입력하고,
  운영자가 버튼을 눌렀을 때에만 localhost Ollama로 요청. 대화 기억(SQLite) 저장 사용.
- **실제 방송 플랫폼에서 채팅을 가져오지 않음.** 프로그램은 플랫폼 계정/API/채널을 연결하지 않음.
- 아직 이 연습 탭은 별도 TTS/아바타에 자동 연결되지 않음. 기존 AI 대화 테스트 탭의
  PC 음성 읽기와 아바타 테스트는 별도 유지됨.

## 검증
\`python -m unittest discover -s tests -v\`
오프라인 모의 응답, 여러 명의 연속 채팅, 동일 내용 반복, 순서, 로컬 모델 실패,
재시도, 출력 실패, 전체 배치 검증, GUI 연결을 자동 시험함.

## 제약
설정 변경/결제/유료 API/OBS 방송 제어/실제 송출/플랫폼 계정 연결/음성 복제 없음.
프로그램을 EXE로 Windows 빌드하는 기존 GitHub Actions는 예약 스케줄 없이 유지.
플랫폼 최종 선택 전이므로 공식 100단계는 **2/100**.
