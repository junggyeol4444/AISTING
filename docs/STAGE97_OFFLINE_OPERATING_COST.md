# v97 / 원본 096 — API·서버·음성 등 운영 비용 관리 (오프라인 부분 구현)

## 원본 기획안과 실제 구현의 차이
원본 `docs/ORIGINAL_PLAN.txt` 8부는 초기 GPU·모델·목소리 구입비와 월별 LLM API·전기·클라우드 서버·TTS 비용이 발생할 수 있다고 설명한다. **가격은 선택에 따라 다르므로 단정할 수 없다는 원칙을 그대로 유지**한다. 기존 014 프로그램·비용 안내(`docs/PROGRAM_COST_GUIDE.md`)는 후보 설명으로 유지하고, 실제 요금 수집 기능과 혼동하지 않는다.

현재 구현은 **운영자 직접 입력값으로 만드는 KRW 추정 계산기**다. 실제 공급자 단가/사용량/청구 내역·부가세·환율·할인·라이선스·장치 전력량·전기요금은 조회하지 않는다. 클라우드 API·외부 서버·계정·결제·프로그램 설치·실제 OBS 방송·사용자 PC 정보/음성 수집은 수행하지 않는다. 계산 입력은 메모리에만 존재하며 파일에 저장하지 않는다.

## 입력 항목과 단위
- LLM 입력 토큰(건수) × 입력 100만 토큰당 단가(원)
- LLM 출력 토큰(건수) × 출력 100만 토큰당 단가(원)
- 서버 사용 시간(시간) × 시간당 단가(원)
- TTS 합성 글자 수(자) × 1,000자당 단가(원)
- 전력 소비(kWh) × kWh당 단가(원)
- 선택 항목: 같은 기간의 예산(원)

모든 입력은 **서로 같은 운영 기간**의 값이라고 운영자가 직접 정한다. 현재 버전에서는 월간·방송 1회 등 기간 설정/변환/자동 집계가 없으며 임의 사용량/단가를 채우지 않는다. 숫자는 0 이상의 십진수(정수부 최대 12자리, 소수부 최대 6자리)로 입력한다. 실제 요금은 KRW가 아닐 수 있으므로 운영자가 직접 환산한 단가가 필요하며 실제 환산율도 검증하지 않는다.

## 과소 계산과 예산 판단 방지
- 사용량 또는 단가가 빈칸이면 해당 항목을 **미산정**으로 표시한다. 사용량이 명시적으로 0일 때만 그 항목을 0원으로 취급할 수 있다.
- 아직 산정하지 못한 항목이 있으면 **알려진 비용 소계는 총액이 아니다.** 소계가 예산 미만이어도 **미확정**으로 판정한다.
- 알려진 소계만으로 예산을 넘는다면, 다른 항목이 미산정이어도 초과 **경고**를 낸다.
- 전 항목이 산정되어 예산 이내여도 어디까지나 **수동 입력에 따른 예상 판정**이며 실제 청구금액 확인/송출 허가/지출 승인이 아니다.
- 합계는 Decimal로 계산한 뒤 소수 둘째 자리(ROUND_HALF_UP)로 표시한다. 결과 개체는 immutable이다.

## 사용자 화면
`운영 비용 수동 예산 계산` 탭 → 운영자가 사용량과 단가/예산을 직접 입력 → `수동 비용 점검`. 입력이 바뀌면 이전 계산 결과를 즉시 무효화한다. 잘못된 입력이나 항목 누락은 오류로 표시하고 이전 결과를 남기지 않는다. 사용자가 버튼을 누르기 전에는 계산하지 않는다.
