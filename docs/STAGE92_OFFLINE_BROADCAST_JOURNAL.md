# v92 / 원본 091 방송 대화 및 사건 기록 저장 — 오프라인 부분 구현

## 원본 및 한계

`docs/ORIGINAL_PLAN.txt` [4-4. 종료 후 처리]에 따르면 방송 후 대화·사건(게임, 슈퍼챗 등)을 기록하여 후속 방송 기억에 사용할 계획이다. 이 단계의 실제 플랫폼 채팅/시청자/후원/게임/OBS 데이터는 **하나도 연결되지 않았다**. 입력은 기존 원본 062 수동 **모의 채팅**과 운영자가 직접 입력한 **가상 사건**으로 한정된다. 기억 추론·검색·다음 방송 연동은 원본 092–093 단계로 미룸.

## 제공 기능

- `방송 대화·사건 기록 (오프라인)` 탭: 운영자 클릭으로만 기존 062 모의 채팅을 복사하거나 게임·가상 후원·운영자 메모·기타 가상 사건을 기록. 플랫폼 순번/중복 내용 보존, 변경된 원본 감지 시 중단, 기록 500건 제한.
- 운영자 명시적 클릭 시 선택 경로에 JSON 저장. 이미 존재하는 파일은 **덮어쓰지 않음**, 저장 폴더 생성이나 설정 파일 변경 없음. 저장/실패 시 메모리 기록 유지.
- 운영자 명시적 선택한 JSON만 읽고 구성·순번·SHA-256 무결성 검증 후 메모리 기록 복구. 읽기 실패 시 기존 메모리 기록 보존. SHA는 **우발적인 손상 감지용**이며 인증·암호화·위변조 방지 보증이 아님.
- `mock_only=true`, `real_platform_collected=false`, `actual_broadcast_verified=false`, `memory_integrated=false`, `auto_saved=false`, `approval=pending` 불변 플래그.
- 새 회차 초기화 시 메모리 기록이 있으면 별도 확인. 원본 캐릭터/음성/플랫폼/아바타/설정·원본 기획안 변경 없음.

## 검증 범위와 유의사항

- 단위 테스트: 가져오기 순서·동일 문구 중복·재가져오기 중복 방지·기존 원본 변경·사건 입력 유효성·용량·수동 저장·복원·훼손/순번/플래그 변경 거부·파일 덮어쓰기 방지·네트워크 차단.
- GUI: Linux Xvfb에서 새 탭, 가상 메모/모의 메시지 저장·복원·손상 파일 거부·설정 저장 없음 확인. Windows/EXE 실제 동작은 미검증.
- 실제 후원·시청자 기록 **아님**. 후원 금액·실제 신원·개인정보·음성 녹음·자동 파일 감시·방송 종료 시 자동 저장 없음. 합법적 보존·동의 정책, 개인정보 삭제/보유기간, 실제 방송 이벤트 연동은 운영자 직접 승인/권리 확인 및 별도 설계가 필요.
- 현재 내보내는 파일은 로컬 JSON 평문이다. 개인/비밀정보를 입력하지 말고 안전한 로컬 위치를 선택할 것. JSON SHA-256은 암호화가 아니다.
- 자동 테스트 통과는 Windows에서 파일 쓰기 권한, 실제 디스크 부족, 백신·동시 접근, 앱 중단 시 완전한 저장 성공을 보장하지 않는다.

원본 091 단계 및 010 최종 사용자 승인 상태는 `pending` 유지. 실제 제품 완성도와 별개로 코드 도달 범위만 91/100. 다음 원본 092 과거 방송을 기억하는 기능 구현.
