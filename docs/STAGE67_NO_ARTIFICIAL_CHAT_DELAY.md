## 원본 요구사항 및 기존 단계 대조

`docs/ORIGINAL_PLAN.txt`의 1부는 **모든 채팅에 반응**, **인위적 지연/선별 기본 적용 금지**, **자연스러움은 운영자가 판단**을 요구합니다. `docs/ROADMAP_100.md`와 `config/roadmap.json`의 066 단계는 `인위적 응답 지연 없이 반응 테스트`입니다. 이전 036 `response_speed_test.py`는 독립 대본 기반 단일 코어 시간 관찰이었고, 이전 065 `offline_chat_reactions.py`는 실제 062 수동 수신함 → 063 순서 기록 → 기존 모의 답변 포트의 FIFO 연결을 검증했습니다. 이번에는 **독립적인 대본/응답기/수신기를 다시 만들지 않고** 그 065 세션의 `reply_next()` 실제 동기 호출 시간을 관찰합니다.

## 구현과 사용

- `src/ai_broadcaster/offline_chat_latency.py`: `OfflineChatLatencyAudit`는 기존 065 `OfflineChatReactions` 객체를 받아 사용자가 누를 때만 `perf_counter_ns`로 **모의 응답 호출** 전후를 측정합니다. 운영자가 명시적으로 선택한 최대 50건만 순차 측정하며 자동 실행·타이머·sleep·자동 재시도·채팅 선별·속도 합격 임계값을 추가하지 않습니다.
- `채팅 무지연 모의 시험` 탭: 기존 061 가상 연결 → 062 수동 입력 → 063 수동 순서 동기화 → 066 탭에서 065 기록 수동 동기화 → 건별/최대 50건 시간 측정. 중앙값, 최소, 최대, P95(최근접 순위)는 관찰값이며 **속도 합격/자연스러움 판정이 아닙니다**.
- 모의 응답 포트가 실패하면 **선두 메시지와 뒤 메시지**를 보존하고 기존 065 탭에서 운영자가 명시적으로 재개해야 합니다. 응답 처리 후 측정 시계가 오류를 반환하면 **이미 처리된 응답을 자동 재처리하지 않고** `미측정 응답`으로 명시합니다. 기존 065 탭에서 직접 응답한 기록도 미측정으로 표시합니다.
- 실제 062/063/065 메모리 원본, 운영자 설정, SQLite, 파일, 기존 아바타/음성 선택값은 수정하지 않습니다. GUI의 측정값은 메모리에서만 유지되며 자동 저장하지 않습니다.
