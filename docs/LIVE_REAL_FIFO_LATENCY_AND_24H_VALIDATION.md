# AISTING 실제 Windows 채팅 FIFO·음성·24시간 실증 경계

이 문서는 기존 네이티브 Windows EXE 사용 절차이며 실사용 성공 인증서가 아닙니다.

## 이번에 연결된 기능
- 치지직·SOOP·Twitch·YouTube 수신은 기존 명시적 연결/중지 버튼과 단일 AI FIFO를 그대로 이용합니다. 모든 독립 메시지를 보존하며 일부 사용자를 무작위로 탈락시키지 않습니다.
- 각 실제 GUI 수신 채팅을 별도의 접수 기록으로 계산합니다. 실제 AI worker에서 접수→작업 시작 FIFO 대기, AI 처리 시작→처리 종료, 총계, 실패를 측정합니다. 실제 수신 중인 원래 앱 경로를 사용하고 fake 모델을 요구하지 않습니다.
- 한국어 [로컬 채팅 실측] 로그는 처음 3건 및 매 25건에 최근 최대 1024건 p95, 전 세션 총 접수·측정·실패·3초 초과 건수와 로컬 수신기 실행시간을 표시합니다. 측정값과 채팅/인증 정보를 파일로 저장하지 않습니다.
- 운영자 Stop은 진단 수집도 정지합니다. 재시작은 통계 신규 시작이며 이전 세션과 혼합하지 않습니다.
- 24시간이라는 경과가 표시되어도 실제 방송이 24시간 유지됐음을 의미하지 않습니다. 수신기의 미연결, 채팅 미유입, 네트워크 끊김, 시청자 실제 음성 수신을 증명하지 않습니다.
- 3초 미만 로컬 계측이 나와도, 메시지가 방송 플랫폼에 게시되거나 OBS 송출/인코딩 후 최종 시청자에게 도착한 시간을 측정한 것은 아닙니다. 반대로 로컬 총계 3초 초과라면 그 건의 종단 간 3초 이내 보장은 불가능합니다.

## 사용자가 실제 성공 여부를 확인할 Windows 작업 순서
1. 기존 main Windows EXE 실행 → 캐릭터 프로필과 원본 공식 Live2D 프로젝트와 참조 대사/합법 참조 WAV·FLAC 설정 확인 → 로컬 GPT-SoVITS 서버가 /tts를 실행하는지 확인.
2. 먼저 새 네이티브 '실제 GPT-SoVITS 음성 단독 합성' 버튼에서 한국어 1문장을 입력하고 해당 참조 음성 이용 권리를 확인하여 1회 승인. WAV 유효성 성공은 음성 합성 확인일 뿐 립싱크/OBS 확인이 아닙니다.
3. 공식 Live2D 창을 열고 OBS의 정확한 오디오 입력·WebSocket 인증 설정 후 '공식 AI·실제 Live2D 입 움직임·OBS 동시 검사' 실행. 실제 같은 발화의 RMS, 입 변화 시간구간, OBS 선택 입력 미터 시간구간이 겹쳐야 관찰 확인으로 기록합니다. OBS 방송 송출이나 시청자 도달은 별개.
4. 소유 YouTube 생방송은 기존 Windows GUI의 'Google 소유 계정 읽기 승인' 버튼을 운영자가 직접 눌러 Google Cloud의 데스크톱 OAuth 클라이언트 ID(필요시 secret)를 입력하고 시스템 기본 브라우저의 공식 Google 동의 화면에서 YouTube 읽기 전용 권한만 승인합니다. PKCE·CSRF state·127.0.0.1 임시 콜백으로 승인 코드를 검증하고 Google token endpoint로 직접 교환한 access token은 앱 실행 중 메모리에만 보관합니다. 자동 로그인/동의/토큰 파일 저장/계정 변경/채팅 발신 없음. 인증에 성공해도 '내 활성 방송'을 선택하고 채팅 수신 시작을 누르는 과정은 별개입니다. 재사용 가능한 refresh token을 저장하지 않으므로 토큰 만료 후에는 재승인이 필요할 수 있습니다. 기존 승인받은 token 직접 입력 방식도 유지됩니다.
5. 실제 수백 명·24시간·1~3초 검증은 운영자 Windows PC의 실제 장시간 프로그램 실행 및 사전 동의된 테스트 방송에서 개별 인입→AI→실제 음성·Live2D→OBS→원격 시청자 수신까지 식별 가능한 발화의 실제 시간표를 측정해야 합니다. 실수신 500건/24시간의 기록이 없으면 해당 항목은 미실증으로 남깁니다. 짧은 2,000건 모의 테스트 또는 Windows CI 통과를 실제 시청자 검증으로 표현하지 않습니다.
