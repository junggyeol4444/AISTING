## 원본 요구와 범위

원본 기획안·원본 `docs/ROADMAP_100.md`의 098 단계는 **여러 차례 방송 반복 안정성 확인**이다.
이미 존재하는 097 `run_virtual_unattended_endurance()`를 반복 호출하고 각 함수가 별도
연결기·수신함·FIFO·응답·시간 규칙·안전 감시·종료 객체를 새로 만드는 구조를 재사용한다.
실제 방송·시스템 시계·자동 예약·실제 AI/TTS·카메라·아바타·OBS·네트워크는 사용하지 않는다.

## 이번에 구현한 내용

- 원본 097의 독립 가상 회차(1시간=3,601틱·채팅 13건, 3시간=10,801틱·37건)를
  **3/5/10회 연속 호출**하며 회차별 결과, 총합, 중복 회차 번호 여부, 완료 여부를 점검한다.
- 한 회차 실패 때 그 회차는 **미통과**, **자동 재시도 금지**. 다음 회차는 독립 가상
  상태로 별도 검증하되 이전 실패로 전체 합격 판정을 복구하거나 오류를 지우지 않는다.
- 테스트에서만 특정 회차의 모의 응답 실패, 순서 커서 손상, 시계 역행, 종료 문구 오류를 주입한다.
  무오류 후속 회차가 이전 실패 상태를 물려받지 않는 것을 확인한다.
- 결과는 **최대 10개 회차 요약**만 보관하며, 샘플 채팅 내용·실제 사용자 자료를 포함하지 않는다.
- Tkinter ‘다회차 방송 안정성 모의 검증’ 탭은 버튼을 눌렀을 때만 실행한다. 반복 횟수/시간
  변경 시 이전 출력은 무효화된다. 기존 사용자 설정은 읽거나 저장하지 않는다.
- 실제 방송이 성공했다는 표시, 영구 실패 체크포인트, 백그라운드 실행, 재부팅 자동 복구,
  네트워크/OBS/API/사용자 PC 수집은 전혀 없다.
