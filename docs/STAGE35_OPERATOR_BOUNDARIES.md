# AISTING 개발 작업 35 · 운영자가 지정한 금기·제한사항

기획안의 3-1, 3-3에 따라 **금기를 AI가 임의로 결정하지 않고 운영자가 직접 입력**하는 오프라인 UI를 추가했다. 금기/제한사항을 입력하지 않으면 어떤 항목도 새로 생성하지 않는다.

## 추가된 기능

- `금기·제한사항 설정` 화면: 한 줄당 한 항목, 최대 12개, 200자/항목.
- 운영자가 수동 미리보기를 누르면 기존 기본/직접 선택 캐릭터·성격·말투·취향과 함께 프롬프트에 입력 원문을 삽입한 구조를 확인.
- 직접 확인한 경우에만 별도 `operator_persona_boundaries.json` 로컬 파일에 저장. 기존 `settings.json`과 SQLite 기억은 건드리지 않음.
- 수동 불러오기, 삭제 전 2회 확인, 삭제 취소, 깨진 파일·과도한 입력·중복 항목·링크 우회 거부.
- 프로그램 시작 시 저장 파일을 자동 읽거나 모델을 실행하지 않음. 실제 모델 생성·출력 필터링·방송 차단 효과는 구현/시험되지 않았으며 해당 사항을 UI에 표시.
- 사용자 선택형 플랫폼·콘텐츠·캐릭터·목소리·아바타 유지.

## 실행과 검증

- 자동: `PYTHONPATH=src python -m unittest discover -s tests -q`
- GUI: `PYTHONPATH=src xvfb-run -a python scripts/gui_operator_boundaries_smoke.py` (Linux, Windows 실제 실행 아님)
- 코드는 외부 서버, 설치, 실방송, OBS 실행, GitHub, PC 정보 조회를 하지 않음.

## 개발 단계 번호 주의

기존 `config/roadmap.json` 및 `docs/ROADMAP_100.md`의 원본 100단계표에는 **34번 ‘운영자가 지정한 금기 설정’, 35번 ‘기본 대화 반응 테스트’**로 되어 있다. 반면 v34의 직전 개발 보고는 34를 ‘반응 방향 설정’으로 기록하고 다음 개발 대상을 35 ‘금기·제한사항 설정’으로 약속했다. 이번 변경은 직전 개발 약속을 따라 **작업 35에 금기 UI를 보강**한 것으로, 원본 계획의 35번 ‘기본 대화 반응 테스트’를 완료했다고 주장하지 않는다. 원본 로드맵 내용과 승인 상태는 임의로 바꾸지 않고 보존한다.

## 승인 구분

개발 작업은 v35까지 진행했으나 사용자가 승인해야 하는 10단계 최종 승인, 11단계 이후 실제 PC 확인, 모델/Windows 실제 검증은 대기다. 개발 범위 표시는 승인 완료 수나 계획의 모든 항목 구현 수와 다르다.
