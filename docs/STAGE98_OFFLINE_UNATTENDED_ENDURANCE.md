# v98 · 원본 097 장시간 무인 방송 테스트 — 오프라인 가속 반복 검사

## 원본 단계의 목표와 구현 경계

원본 `docs/ORIGINAL_PLAN.txt` 및 `docs/ROADMAP_100.md`의 097 단계는 **장시간 무인 방송 테스트**이다.
이번 개발에서는 이전 059 아바타 가상 반복 시험 및 083/090 일회차 통합 감사와 달리,
**기존 062 수신 → 063 FIFO → 065 모의 응답 → 078 시간 판정 → 079 마무리 → 095 안전 감시**
실제 로컬 모듈을 긴 **가상 시간 동안 반복 호출**하는 감사 기능을 새로 구현했다.
이전의 독립 실행 기능이나 원본 사용자 설정을 중복 구현/변경하지 않는다.

## 구현과 실측 범위

- `src/ai_broadcaster/offline_unattended_endurance.py`의 `run_virtual_unattended_endurance(1|3)`는
  내부 메모리에 **새로운 독립 모의 세션**을 하나씩 생성하여 가상 시간 `0..3,600` 또는
  `0..10,800`초에 대해 **매 가상 초마다 검사**한다. 이 반복은 실제 시간의 경과가 아니다.
- 300 가상 초마다 모의 채팅 1건을 생성하여 수신 순번/FIFO 승인/응답/안전 감시를 확인한다.
  1시간에서 접수·응답 각각 **13건**, 3시간에서 각각 **37건**이며 메시지 내용은 의도적으로 같아도
  개별 이벤트로 유지된다. 테스트용 닉네임/문구만 사용한다.
- 안전 감시가 정체·기록 불일치·연결 변경을 판단하거나 모의 답변/시계/마무리 표시가 실패하면
  **성공으로 판정하지 않고 즉시 중단**한다. 자동 재생성/재시도/실제 방송 제어는 없다.
- 모든 모의 채팅을 처리하고 최대 가상 시간 도달 후에만 기존 079 상태 기계에서
  마무리 예고와 작별 인사를 각각 표시했다고 가상으로 확인한 다음 **가상 종료 상태**를 검사한다.
- 결과는 **최대 12개 표본**만 보관하고 본문에는 채팅/시청자 내용을 넣지 않는다.
  메모리의 모의 채팅 이벤트 수는 1~3시간 실행 시 13~37건(기존 수신 한도 500건 이하)이다.
- `장시간 무인 방송 모의 안정성` 탭의 수동 버튼으로 1시간·3시간 중 선택해 검사한다.
  그 버튼은 자동 개발 예약, 운영체제 시간 감시, 방송 시작, 알림 예약이 아니다.
- 진단용 오류 주입은 응답 실패, 순번 커서 손상, 단조 시계 역행, 마무리 표시 실패다.
  오류 뒤 다음 실행은 **새로운 독립 가상 세션**이며 실패한 방송을 자동 복구하는 것이 아니다.

## 할 수 없는 검증

이 개발은 가상 3시간이 **0.1초대**에 완료될 수 있는 CPU 반복이며,
3시간 동안 프로그램을 실행하거나 사람이 없는 실제 방송을 진행한 적이 없다.
가속 모의 검사가 통과해도 실사용에서 나타나는 메모리 누수, 스레드 축적, 장치·네트워크 지연,
Windows 절전/재시작, SQLite 커넥션 문제, 실제 TTS·OBS·아바타 지연/품질, 권리·안전 문제는
증명되지 않는다. 이 단계에서는 Windows 실행, OBS 송출, PC 정보 수집, 계정 연결,
실제 음성 자료 수집·결제·외부 API·GitHub 및 OS 프로그램 설치를 수행하지 않았다.

개발 컨테이너에서 `tracemalloc`으로 가속 모의 3시간 실행을 연속 다섯 번 관측했다.
이 실행의 Python 메모리 계측 결과는 `logs/STAGE98_VIRTUAL_AUDIT.log`에 그대로 남겼으며
이는 **짧은 모의 함수의 Python 할당량**일 뿐, 프로그램 전체 RSS·Windows/장치
메모리의 실제 장시간 누수 검증이 아니다.
기존 SQLite `ResourceWarning: unclosed database`는 전체 자동 테스트에서 **여전히 관측됨**.

원본 097 체크박스와 `config/roadmap.json` 상태는 `pending` 그대로이며 사용자 승인 010,
Windows 실기기·실제 무인 1~3시간 방송 검증은 별도 대기 상태이다.
**코드 개발 도달 범위 97/100은 실제 제품 완성률을 나타내지 않는다.**

다음 원본 단계: **098 여러 차례 방송 반복 안정성 확인**.

## 검증 방법

프로젝트 폴더에서 `PYTHONPATH=src python -m unittest discover -s tests -q` 실행.
GUI 가능한 환경에서 `xvfb-run -a env PYTHONPATH=src python scripts/gui_offline_unattended_endurance_smoke.py`.
리눅스 Xvfb 결과는 Windows Tkinter/EXE 검증과 별개이다.
전체 기록과 실패 주입 결과는 `logs/STAGE98_*`를 참고한다.
