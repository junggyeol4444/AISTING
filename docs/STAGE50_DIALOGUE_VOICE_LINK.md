# AISTING v50 — 원본 049단계: AI 대사와 음성 출력 연결 (오프라인 모의)

## 이번에 개발한 코드

- `src/ai_broadcaster/dialogue_voice_link.py`의 `DialogueVoiceLink`에서 **기존 모의 채팅 대본 파서 → 기존 MockReplyGenerator → 기존 선택 음성 가상 라우팅**을 FIFO로 연결한다.
- ‘AI 대사·음성 연결 모의’ Tk 탭: 직접 수정 가능한 `닉네임: 채팅` 대본(최대 30건), 가상 시험용 목소리 식별자(실제 설치 여부와 무관), 오류 시나리오, 초기화·1건 수동 처리/재시도·사용자 버튼에 의한 일괄 처리.
- 중복 채팅을 합치거나 건너뛰지 않는다. 응답은 처리 순서대로 가상 출력에 전달하며, 모든 구간의 가상 전달이 성공한 경우에만 채팅 1건을 완료 처리한다.
- 중단 또는 가상 오류 시 현재 모의 답변, 이미 처리된 구간, 실패 구간과 뒤쪽 채팅을 보존한다. 사용자가 다시 처리 버튼을 눌렀을 때만 **미처리 구간부터 재개**한다. 이미 처리한 구간의 자동 반복과 자동 재시도 없음.
- 음성 출처/가상 목소리 이름/속도/음량/대본/오류 시나리오 변경 시 GUI 시험 세션 무효화. 존재하지 않는 선택 음성 자동 대체 없음.
- 실제 AI 모델 호출·Ollama 접속·실제 목소리 조회·오디오/스피커/파일/SQLite/녹음/음성 복제/방송/OBS/계정 연결 **전혀 없음**.

## 구현/검증 경계

이번 코드는 **기존 모의 AI 답변을 기존 선택 한국어 목소리 모의 출력 경로로 안전하게 묶는 구조 검증**이다. `가상 시험 목소리 식별자`는 운영자 PC에 설치된 목소리 인증이 아니다. 실제 AI 대사 생성·실제 한국어 TTS 재생·입 모양 동기화·방송 장면 전달·자연스러움 검증/운영자 승인은 완료되지 않았다. 실제 Windows 실기기/EXE 검증도 미수행.

기획안의 기본 ‘모든 채팅에 자연스럽게 반응·인위적 지연 없음’ 원칙 유지. 모든 선택형 플랫폼·콘텐츠·캐릭터·목소리·아바타·기존 설정·SQLite 기억·원본 기획안 유지.

- **개발 범위 도달: 원본 049/100** (사용자 승인 완료 비율 아님).
- **승인 대기:** 원본 010 전체 최종 승인, 011 이후 사용자 PC 정보 확인, 실제 음성 사용권/학습/품질과 Windows 실기기 확인.
- 다음: 원본 050 ‘목소리 작동 최종 검증’ 중 승인 불필요한 오프라인 검증. 실제 음질 판단은 사용자 직접 평가.
