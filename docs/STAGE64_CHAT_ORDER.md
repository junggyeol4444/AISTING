# v64 · 원본 063 메시지 처리 순서 관리 — 수동 오프라인 FIFO 검증

## 원본 계획과 중복 방지

`docs/ORIGINAL_PLAN.txt`, `docs/ROADMAP_100.md`, `config/roadmap.json`, 기존 README 및 061/062 검증 기록을 확인했습니다. 원본의 **모든 채팅에 반응, 인위적 지연/선별 금지** 원칙을 유지합니다. 061 가상 연결 및 062 수동 수신함을 그대로 재사용하며, 새 채팅 수신기를 만들지 않습니다.

## 구현

- `src/ai_broadcaster/offline_chat_order.py`: 062의 메모리 수신함에서 **사용자가 누른 때만** FIFO 스냅샷을 동기화합니다. 수신 순번의 연속성/기존 접수 기록의 불변성을 검사하고 오류 시 원래 순서와 처리 커서를 보존합니다.
- 수동 `다음 1건 순서 확인`: 플랫폼을 섞어 접수해도 원본 순번대로 1건만 확인 처리합니다. 내용이 같은 채팅도 독립된 건으로 유지합니다. 확인 처리와 AI 답변 완료는 다릅니다.
- 수동 `다음 1건 모의 실패`: 처리 커서를 옮기지 않고 실패한 현재 채팅과 이후 채팅을 보존합니다. 오류 중에는 자동 재시도 없이 명시적인 `수동 재개` 버튼으로만 계속할 수 있습니다.
- 새 채팅은 062 수신함에 남으며, 다시 수동 동기화해야만 063의 확인 대기열에 추가됩니다. 연결 해제/선택 변경 뒤에도 이미 접수한 채팅과 대기열을 보존합니다.
- `desktop.py`의 `메시지 순서 관리` 탭은 버튼/상태/최근 대기 10건을 표시합니다. 기존 플랫폼·콘텐츠·캐릭터·음성·아바타 설정, SQLite 기억 및 기획 문서는 변경하지 않습니다.

- 따라서 원본 063 체크박스와 `config/roadmap.json`의 `pending`은 그대로 두고, **코드 개발 도달 범위만 63/100**으로 기록합니다. 사용자 승인 010 및 사용자 PC 검증은 별도 대기입니다.
