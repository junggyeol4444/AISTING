# AISTING 누적 v43 — 원본 계획 042 '승인된 음성 자료 준비'

## 실제 구현된 범위: 메타데이터 기반 수동 준비표

- `src/ai_broadcaster/voice_material_plan.py`: 사용자가 **직접 입력한 음성 자료별칭과 예상 길이(초)**, 짧은 준비 메모만 다루는 독립 모듈. 1~20개 항목, 각 1~600초 정수. 총 길이는 예상값의 단순 합계.
- Tkinter의 신규 `음성 자료 준비표` 탭: 수동 입력·미리보기·확인 후 초안 JSON 저장·수동 불러오기·2회 확인 삭제·입력 초기화.
- 기존 **41단계 권리 체크 기록은 사용자가 버튼을 누를 때만 읽고**, 현재 `방송 설정`에 선택된 목소리 출처가 일치할 때만 참고. 다른 출처의 준비표를 불러오거나 권리 점검을 재활용하지 않음. 출처 변경 시 화면 입력·참고 권리 정보를 초기화(디스크상 기존 데이터는 보존).
- 권리 체크가 전부 채워졌어도 **운영자 자체 신고**일 뿐 합법적인 음성 사용권이나 원본 파일의 준비 완료를 증명하지 않음.
- 파일명을 입력하지 말도록 별칭만 받으며, `:`, `/`, `\\`, `@`, `|`, `..` 등 경로·주소 오용을 막음. 단, 자유 입력에서 개인정보를 자동 감지할 수 없으므로 운영자가 입력하지 않아야 함.
- 전용 파일 `voice_material_draft.json`에는 별칭·초 단위 예상 길이·메모·출처만 저장. `audio_files_stored=false`, `training_authorized=false`, `broadcast_authorized=false`를 기록하고 엄격한 스키마 검증·크기 제한·경로 링크 차단·임시 파일 원자 교체를 수행.
- 이 화면은 실제 파일 선택/검색/열기/복사·녹음·재생·학습·합성·클로닝·설치·방송·플랫폼 연결·PC 정보 조회를 **하지 않음**. 앱 시작 시 준비표/권리 점검을 자동 읽지 않음.
- 기존 사용자 설정 `settings.json`, SQLite 기억, 원본 기획안, 플랫폼/콘텐츠/캐릭터/음성/아바타 선택은 유지.

## 안전을 위한 오해 방지

‘승인된 음성 자료 준비’라는 원본 단계 제목은 **실제 음성 자료의 사용 권한과 실물이 확인되었다는 뜻이 아님**. 이번 개발로 구현한 것은 사용자가 실물을 다루기 전 단계의 **메타데이터 준비표**뿐이다.
