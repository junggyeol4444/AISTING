# AISTING 누적 ZIP v41 — 원본 개발 계획 040: 캐릭터 대화 1차 검증

## 구현 범위

기존 원본 로드맵의 040 ‘캐릭터 대화 1차 검증’을 위한 **운영자 주도 오프라인 모의 검증**을 추가했다.
코드는 `src/ai_broadcaster/character_dialogue_review.py`, 화면은 기존 `desktop.py`의
`캐릭터 대화 1차 검증` 탭이며 새 자동 테스트와 GUI 스모크 테스트를 포함한다.

1. 운영자가 ‘방송 설정’ 탭에서 선택한 **기본/직접 입력 캐릭터**와 화면의
   **취향**, **상황별 반응 방향**, **금기·제한사항 입력란**을 한 번의 검증용 지침으로 합성하고 미리 본다.
   기존 파일의 금기·피드백 기록을 자동 불러오거나 반영하지 않는다. 사용자가 직접 불러온 입력만 사용한다.
2. `닉네임: 채팅` 대본을 직접 수정하고 버튼을 누르면 기존 035 모의 대화 엔진을
   **독립된 메모리 전용 세션**에서 재사용한다. 답변 FIFO·중복 보존·최근 8건 맥락 전달 및 오류 중단 후
   실패 채팅 대기열 보존을 구조 검사한다. 30건 제한은 기존 035 검사와 같다.
3. 운영자는 순번별로 `검토 대기`, `자연스러움 확인`, `수정 필요` 중 하나와 메모를
   **직접 표시**할 수 있다. 평가가 모두 입력되어 구조 검사가 성공해도 ‘운영자 모의 답변 긍정 평가’로만
   표현하고 **최종 개발 승인·실제 AI 자연스러움 합격**으로 처리하지 않는다.
4. 캐릭터·취향·반응 방향·금기·시험 대본을 변경한 뒤 평가 표시를 시도하면 이전 검증과
   평가를 무효화하고 재시험을 요구한다. `예시 복원·평가 초기화`도 메모리 내 상태만 초기화한다.
5. 기존 `settings.json`, SQLite 기억, 금기 JSON, 운영자 피드백 JSON을 자동 읽거나 변경하지 않는다.
   **모의 답변 생성기는 검토용 캐릭터 지침을 실제로 적용하지 않는다.** 지침이 응답에 반영되었다고 주장할 수 없다.

- 010 최종 승인 및 사용자 PC 정보 확인은 **사용자 직접 결정·실기기 검증 대기**.
