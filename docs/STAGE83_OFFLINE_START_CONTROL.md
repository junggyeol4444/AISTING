# v83 / 원본 082 자동 방송 시작 제어 — 수동 오프라인 모의 기능

## 기획안과 비교

원본 기획안은 요일/방송 시간 판단 → 시작 전 공지 → OBS 시작 → AI 코어 가동의 **실제 자동화**를 요구한다. 현재 사용자가 금지한 서버·계정·OBS·송출 및 미승인 설치·PC 정보 수집 없이 위 전체를 구현/검증할 수 없다. 이번에는 081에서 구현한 일정 초안을 *읽기만 하는* 시작 시각 판단 및 가상 시작의 차단·실패 처리를 개발했다. **코드 개발 도달 범위 82/100, 원본 082 실제 완료 아님**.

## 실제 구현 내용

- `src/ai_broadcaster/offline_start_control.py`: 독립 메모리 제어기 `OfflineStartController` / 불변 `StartDecision`. 운영자 수동 입력 `YYYY-MM-DD HH:MM`만 사용하며 시스템 시각을 읽지 않는다.
- 등록 요일과 정확히 같은 시각에 한해 `mock_ready`. 허위 자동실행·방송·외부 게시 설정이 참이거나 누락/형식 오류이면 `blocked`. 다른 시각·요일이면 `not_due`, 가상 진행 중이면 `mock_active`, 동일 시각 재실행이면 `duplicate`.
- 사용자가 직접 누르는 `가상 시작` / `가상 종료` 버튼만 동작한다. 가상 표시 콜백에서 실패하면 해당 시각을 소비하지 않고 `display_failed`로 판정한다. 성공 시 기록은 메모리에만 남고 JSON/원본 설정을 쓰지 않는다.
- 081 '방송 시작 일정 초안' 탭에 082 점검/가상 시작/가상 종료 버튼을 추가했다. 초안 수정 시 가상 제어기를 교체하고 결과를 무효화한다. 수동 기준일시 변경 시 표시된 이전 판정만 무효화한다.
- `scheduled_execution`, `streaming_enabled`, `external_publish_enabled` 값을 **절대 켜지 않는다**. 백그라운드 감시/실제 일정 등록/송출/음성 출력/OBS/계정/네트워크/PC 스캔/파일 저장은 수행하지 않는다.

## 의도적으로 아직 미구현/미검증

실제 자동 시작 제어 엔진/운영체제 스케줄러, 시계 경계 경쟁 조건, 프로그램 재시작 후 가상 처리 이력 영구 보존, 시간 변주·휴무 정책, 실제 공지·OBS·플랫폼·AI 가동, Windows EXE 실기기 검증. 동시간대 중복 거부도 앱 프로세스의 *메모리 내부* 범위일 뿐이다. `mock_started`와 방송 성공을 동일시하지 말 것. 실제 자동 시작은 사용자 별도 승인 전까지 금지.
