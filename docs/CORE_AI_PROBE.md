# 24단계 — AI 연결 시험 (승인 게이트 및 오프라인 검증)

## 구현 범위

`core_ai_probe.py`에 **네트워크가 없는 `/api/tags` 프로토콜 시뮬레이터**, 엄격한 JSON 응답 검사, **운영자 승인 후에만** 동일 PC 로컬 Ollama를 조회하는 단발성 시험 코드를 추가했습니다. `AI 연결 시험` 탭은 23단계 화면의 현재 연결 방식과 모델 이름을 참조합니다. 탭 진입이나 앱 시작 시 조회는 전혀 없습니다.

- **오프라인 가상 응답 시험:** `available` / `missing` / `invalid` / `http_error` 시나리오. 가상 모델 일치 결과는 실제 모델 설치·연결 성공이 아닙니다. GUI 기본 버튼은 `available` 가상 응답 형식 검증만 수행합니다.
- **실제 PC 로컬 조회:** 운영자가 `로컬 Ollama (수동 선택)`과 모델 이름을 입력하고, 별도 버튼을 누른 후 **확인 대화상자에서 동의할 때만** `127.0.0.1:11434/api/tags`에 단 한 번 GET합니다. 응답에서 사용자가 입력한 **정확한 모델 이름**만 비교합니다. 실제 시험을 이 개발 실행에서 수행하지 않았습니다.
- **보안 제한:** 고정 IP/포트/경로, 2초 연결/읽기 시간 제한, 256 KiB + 1 바이트 읽기 상한, JSON `models[].name` 검증, HTTP 200 이외 성공 금지, 리다이렉트 미추적, 프록시 미사용. 응답 오류/모델 미발견/접속 거절은 성공으로 표시하지 않습니다. 계정 인증·외부 서버·모델 다운로드/생성·프로세스 실행·설치·OBS 방송을 하지 않습니다.
- **승인 보호:** `probe_local_model()`은 `operator_confirmed=True`가 없으면 `PermissionError`를 발생시키고 네트워크 함수도 호출하지 않습니다. GUI의 확인 취소 시 같은 동작. 테스트에서는 네트워크 대신 주입한 가짜 transport를 사용했습니다.
- **기존 상태 보존:** 결과는 현재 GUI 메모리에만 표시합니다. 기존 코어는 여전히 `MockCoreReplyPort`를 사용하며 FIFO, 대화 이력, 방송 설정, SQLite 기억, 선택형 플랫폼/콘텐츠/캐릭터/음성/아바타, 17·23단계 프로필 파일은 바꾸지 않습니다.

## 한계 및 운영 승인 대기

`/api/tags` 조회는 **로컬 서비스의 응답 형식과 모델 이름 등록 여부**만 확인합니다. 모델이 실제로 한국어로 답변 가능한지, 모델 생성 요청이 성공하는지, GPU 성능이나 Windows 실행 적합성은 확인하지 않습니다. 설치되지 않은 로컬 Ollama를 자동 실행하지 않습니다. 실제 Windows PC에서의 조회/모델 작동/EXE 검증은 **미실행**이며 운영자 확인 대기입니다.

10단계 전체 개발 기준 최종 승인은 미승인, 11단계 이후 실제 PC 확인도 `pending`, 공식 9/100 유지입니다. 24단계 전체 완료로 표시하지 않습니다. 후속 25단계 한국어 대화 시험도 별도 작업입니다.

## 개발 환경 검증

`python -m unittest discover -s tests -q`로 단위 테스트, `xvfb-run -a python scripts/gui_core_ai_probe_smoke.py`로 가상 GUI 테스트, 기존 GUI 회귀 테스트를 실행합니다. `tests/test_core_ai_probe.py`는 승인 전 무호출, 모의/승인 주입 전송, 리다이렉트·비JSON·초과 크기·모델 이름 불일치·타임아웃·오류를 검사합니다. 개발 환경에서 실제 로컬 포트로 요청하지 않습니다.
