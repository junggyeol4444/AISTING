# v101 / 원본 100단계 — 최종 기능 검수 자료, **운영자 승인 대기**

## 원본 요구사항

원본 `100 최종 기능 검수 및 운영자 승인`은 **실제 기능 검수 + 운영자의 명시적 승인**을 요구한다. 이번 버전은 운영자의 승인 이전에 진행할 수 있는 *오프라인 검수 자료 구성과 출시 차단 검사*까지만 구현하였다. 개발자가 버튼을 눌러 사용자 승인을 대신하거나, 테스트 통과 수를 실제 방송 가능 증명으로 바꾸지 않는다.

## 실제 구현

- `src/ai_broadcaster/offline_final_acceptance.py`: 14개 검수 영역과 미구현/미검증/미해결 항목의 명시적 보고서, 원본 로드맵 010/100 `pending` 여부 검사, 개발 환경에 보관된 문서/로그 **6개 지정 경로만**의 존재 및 SHA256 조회, 기존 SQLite 미종료 경고를 차단 사유로 유지.
- `src/ai_broadcaster/desktop.py`: `최종 기능 검수·승인 대기` 화면에서 버튼을 눌렀을 때만 동봉 프로젝트 문서를 검사하고 보고서를 표시. 원할 때만 덮어쓰지 않는 JSON 검토 자료 저장. 기존 099 운영자 점검 자기보고와 대조하지만 자기보고를 실기기 증거로 인정하지 않는다.
- `tests/test_offline_final_acceptance.py`: 28개 신규 단위 테스트. 외부 연결·프로세스 호출 없음, 누락·변조·symlink·용량 초과·손상 로드맵, 운영자 모든 항목 체크 시에도 승인/출시 차단, JSON 덮어쓰기 차단, 보고서 변조 차단, 사전 진단 외부 파일 읽기 없음.
- `scripts/gui_offline_final_acceptance_smoke.py`: Tkinter GUI 탭·검토 버튼·12항목 전부 자기보고 상태 후에도 승인 불가·검토 자료 수동 저장·덮어쓰기 거부·기존 설정 보존 테스트.

### 증빙의 강도 제한

원본 SHA256 유지/로드맵 `pending` 감지/검증 로그 존재를 확인한다. **보관 로그가 있다는 사실은 실제 테스트를 지금 다시 실행했다는 뜻이 아니다.** 재실행은 별도의 개발 도구에서 실제로 실행해 아래 검증 로그로 기록하였다. Linux/Xvfb GUI 결과는 Windows 실제 장치의 화면·소리·방송 검증을 대체하지 않는다. 자동 사용자 PC 검사/로그 수집/시스템 진단은 수행하지 않는다.

### 절대 승인으로 처리하면 안 되는 항목

| 검수 영역 | 이번 개발 환경에서 확인 가능 | 운영자/실기기 검증 상태 |
|---|---|---|
| 기획안·로드맵 보존 | 동봉된 파일 SHA256 검사 | 원본 승인은 pending |
| 소스·테스트 회귀 | 개발 환경 unittest / Linux Xvfb | Windows 실행 미검증 |
| 사용자 설정·자료 | 가상 설정/샘플 보존 시험 | 실제 PC 백업·복구 미검증 |
| 방송 플랫폼 채팅 | 가상 FIFO·순서·복구 | 실제 채팅 미연결/미검증 |
| 로컬 AI | 규칙 기반 모의 응답 | 모델 설치/자연스러움/안전성 미검증 |
| 한국어 TTS | 가상 음성 문구·선택값 | 실제 소리·발음·라이선스 미검증 |
| 아바타 | 2D Tk Canvas 예시·3D 자리표시자 | 실제 모델/립싱크 미검증 |
| 방송 송출 | 메모리 가상 시작·가상 종료 | OBS·비공개/실제 방송 미검증 |
| 게시 연동 | Discord/네이버 공지 형식 초안 | 인증·실제 게시·권한 미검증 |
| 장기기억·안정성 | 모의 JSON·가속 회차 시험 | 실제 AI 기억·장시간 실가동 미검증 |
| 운영 안전·자원 | 모의 이상 감지·복구 | SQLite 미종료 경고 해결 필요 |
| 권리·비용·승인 | 수동 체크리스트·예상 비용 | 실제 권리/요금/사용자 최종 승인 미완료 |

`can_release=false`, `approval_granted=false`, `hardware_verified=false`, `actual_broadcast_verified=false` 고정. 운영자 점검 12건 전부 `확인 입력`이더라도 이 값은 바뀌지 않는다.

**원본 `docs/ORIGINAL_PLAN.txt`, `config/roadmap.json`(모든 승인 상태 `pending`)과 기존 사용자 선택 기능을 보존한다.** 원본 010 최종 사용자 승인과 100단계 최종 운영자 승인은 그대로 `pending`이다. 로드맵 100/100은 코드 개발 단계의 도달 범위만 뜻한다. **실제 제품/방송 완성률 100%가 아니다.**

## 검증

`logs/STAGE101_FINAL_VALIDATION.txt` 및 `logs/STAGE101_UNITTEST.log`, `logs/STAGE101_GUI_*.log`, `logs/STAGE101_SYNTAX.log`를 참조. 실제 사용자 기기 연결·윈도우 설치·권리·자연스러움/장시간 테스트는 수행하지 않는다.

v101 작성 당시의 미종료 경고는 이후 재현 분석에서 `test_response_records.py`의 테스트 연결 5건으로 확인되어 v102에서 닫도록 수정했다. `_readonly()` PRAGMA 실패 시 닫기 보완도 적용했다. 이전 기록은 당시 상태를 설명하는 역사적 로그로 보존한다. **Windows 실기기 장시간 DB 안정성은 여전히 미검증이며 출시/승인은 차단**한다.
