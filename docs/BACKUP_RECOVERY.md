# 19단계 · 로컬 백업 검증 및 비파괴적 복구 준비 (v19)

이 기능은 **18단계에서 운영자가 직접 만든 보관 ZIP**을 대상으로 합니다. 프로그램 실행·탭 열기만으로 PC 파일을 자동 수집하거나 백업·복구하지 않습니다. 기존 방송 설정, 기획안, SQLite 기억, 사용자 선택값을 수정하지 않습니다.

## 사용 방법

1. `화면 이동 → 백업·복구 준비` 탭으로 이동합니다.
2. 백업이 없다면 `새 백업 만들기 (18단계 화면으로 이동)`를 눌러 `기획안·설정 보관` 화면에서 필요한 항목을 선택하고, 저장 위치와 확인 대화상자를 거쳐 ZIP을 만듭니다. 이 단계는 기존 18단계 기능을 재사용합니다.
3. `백업 ZIP 선택`에서 본인이 만든 AISTING 수동 보관 ZIP을 지정합니다. 선택만으로는 읽거나 복원하지 않습니다.
4. `백업 무결성 검사 (읽기 전용)`를 누르면 ZIP 항목, 필수 3개 문서, SHA256/CRC, 파일 크기 및 JSON·로컬 실행 정책을 확인합니다. 검사만으로 파일을 생성하지 않습니다.
5. `새 폴더에 복구 사본 만들기 (수동)`를 누르면 상위 폴더를 **직접 선택**하고 **별도로 확인**한 경우에만 `AISTING_Recovery_Staging` 폴더를 새로 만듭니다. ZIP 내부의 허용된 문서·선택형 설정 사본과 `RECOVERY_NOTE.txt`가 이 폴더에 들어갑니다.
6. 복구 사본은 **운영자가 비교·검토하기 위한 것**이며 앱 실행 설정에 자동 반영되지 않습니다. 필요 시 향후 별도 승인 절차에서 실제 복원 방식을 결정합니다.

## 보호 장치

- 기존 동명 `AISTING_Recovery_Staging` 폴더가 있으면 생성하지 않습니다. 기존 ZIP/원본/앱 설정/SQLite를 덮어쓰거나 삭제하지 않습니다.
- ZIP 내부 경로를 그대로 추출하지 않고 **미리 지정된 3개 필수 + 최대 2개 선택 경로만** 허용합니다. 경로 이동(`../`), 중복, ZIP 내 링크, 암호화 파일, 손상·변조, 해시 불일치, 과도한 크기를 차단합니다.
- 백업 ZIP 및 출력 경로의 심볼릭 링크·Windows 정션/재분석 지점을 거부합니다. 생성 중 오류가 나면 이번 작업에서 새로 만든 사본 폴더만 정리합니다.
- 압축된 개인 설정에는 민감한 사용자가 입력한 문자열이 포함될 수 있으므로 공유하지 않는 편이 안전합니다.
- **대화 기억 SQLite, 채팅 기록, 운영체제/CPU/RAM/GPU, 10단계 승인 기록, 계정 토큰**은 현재 ZIP 백업에 포함되지 않습니다. 따라서 이 기능을 전체 PC 데이터 복구나 실제 서비스 복원으로 표현하지 않습니다.
- 앱 실행 시 자동 백업·정기 백업·자동 복원·프로그램 설치·외부 접속·GitHub·결제·OBS 방송은 없습니다.

## 검증 범위

- `tests/test_backup_recovery.py`: 사용자 확인, 읽기 전용 검사, 안전한 복구 사본 생성, 기존 데이터 보존, 변조/경로 이동/중복/링크/크기 제한/오류 정리 등을 검증합니다.
- `scripts/gui_backup_recovery_smoke.py`: Linux Xvfb 가상 Tkinter 화면에서 탭 이동, 선택/취소, 무결성 검사, 수동 사본 생성, 기존 파일 보호를 검사합니다.
- **Windows 10/11 실기기 실행, EXE 빌드, 사용자 PC의 실제 백업/복구 및 SQLite 복구는 검증하지 않았습니다.** 10단계 승인과 11~19단계 사용자 PC 확인은 `pending`입니다. 공식 진행률은 **9/100**입니다.
