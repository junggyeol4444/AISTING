# v69 / 원본 068 — 여러 시청자 대화 처리 (오프라인 모의)

## 기준과 재사용 범위

원본 기획안 `docs/ORIGINAL_PLAN.txt` 1부의 원칙: **모든 채팅에 반응**, 인위적인 기본 딜레이·선별을 넣지 않으며, 자연스러움은 운영자가 판단합니다. `docs/ROADMAP_100.md`/`config/roadmap.json` 원본 068은 `여러 시청자 대화 처리`입니다. 이전 062의 메모리 수동 수신함, 063의 전체 FIFO 순서, 065의 모의 응답 포트, 066의 무지연 수동 측정, 067의 동일 `(플랫폼, 닉네임)` 성공 응답 맥락을 **새 수신기나 별도 큐 없이** 재사용합니다.

## 실제 변경

- `src/ai_broadcaster/offline_multi_viewer.py`: `OfflineMultiViewerDialogue`는 운영자 수동 `activate()` (067 시청자별 맥락), `sync()` (기존 063/065 동기화), `reply_next()`, `reply_batch()` (기존 최대 50건), `resume()` (실패 후 수동 재개)를 제공합니다. 각 동작은 기존 단일 FIFO 응답 세션에 위임합니다. 시청자별 병렬 큐/스케줄러/자동 재시도/우선순위/채팅 필터는 만들지 않았습니다.
- `snapshot()`은 기존 수신/응답 기록을 **읽기 전용**으로 집계합니다. 시청자별 접수·동기화·성공 응답·대기·미동기화 순번을 제공하고 전체 선두를 보여 줍니다. 미동기화 건은 누락이나 처리 완료로 표시하지 않습니다. 보고서에는 앞 15명의 요약만 표시하되, 기록/처리 대상에서 다른 시청자를 제외하지 않습니다.
- 기존 067의 직전 성공 응답 최대 8건만 같은 플랫폼·닉네임으로 전달합니다. 동명이인/닉네임 변경/실제 계정 인증을 해결하지 않습니다. 실패한 채팅은 맥락에 들어가지 않으며 선두와 뒤의 모든 채팅이 보존됩니다.
- `src/ai_broadcaster/desktop.py`: `여러 시청자 대화 모의` 탭을 추가했습니다. 기존 탭과 저장 설정은 그대로입니다. GUI 버튼은 모의 실행만 하며 외부 플랫폼/AI/OBS로 연결하지 않습니다.

## 운영자 수동 시험 절차

1. 방송 설정에서 치지직·유튜브·트위치를 필요에 따라 복수 선택합니다. `플랫폼 채팅 연결 모의`에서 **가상 연결**하고 `채팅 수신 모의`에서 수신 준비합니다.
2. `채팅 수신 모의`에서 서로 다른 가상 닉네임으로 채팅을 번갈아 1건씩 입력합니다.
3. **첫 응답 전에** `여러 시청자 대화 모의` 탭에서 시청자별 맥락을 수동 활성화하고 수신·순서를 동기화합니다.
4. 한 건씩 또는 최대 50건씩 수동 모의 응답합니다. 시청자별 집계와 전체 FIFO 선두를 확인합니다. 모의 실패 버튼으로 실패를 만들면 뒤의 모든 채팅을 보존하고 수동 재개 후 다시 응답합니다.

## 제한 및 승인 구분

- 이 단계는 **오프라인 수동 모의 채팅**을 여러 가상 닉네임으로 처리하는 코드 검증입니다. 실제 시청자 동시 접속, 플랫폼 메시지 수신, 실제 LLM 대화 이해·장기 기억, 성능/동시성/실시간성, 음성/아바타/OBS 방송 검증이 아닙니다.
- 수동으로 1~50건 처리하는 동기 호출이며 실방송 규모에서 GUI 반응성·지연·처리량은 검증하지 않았습니다. 메모리 수신함 최대 500건, 기존 성공 맥락 최대 8건 한도는 그대로입니다.
- 네트워크·계정·GitHub·외부 AI·프로세스·결제·사용자 PC 접근·승인 없는 설치/자료 수집 없음. 기존 원본 기획안, 사용자 설정, 플랫폼/콘텐츠/캐릭터/음성/아바타 선택은 보존합니다.
- 로드맵 원본 068/010 승인 상태는 `pending`; **코드 개발 도달 68/100**과 실제 운영/Windows/EXE/사용자 승인 완료는 구분합니다.
