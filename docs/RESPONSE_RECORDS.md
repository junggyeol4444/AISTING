# 28단계 — 응답 기록 저장 (별도 로컬 SQLite, 수동 승인)

## 구현 범위

`src/ai_broadcaster/response_records.py`는 **기본 코어 수동 실행 탭**에서 이미 성공한 모의 답변만 별도의 `core_response_records.sqlite3` 파일에 기록합니다. 앱 시작·탭 이동·코어 실행·대본 추가·오류 재시도·저장 후보 미리보기에는 **파일 기록이나 조회가 없습니다**. 사용자가 `응답 기록 저장` 탭에서 `확인 후 응답 저장`을 누르고 확인 대화상자에 동의한 경우에만 DB를 생성/수정합니다. 실제 방송, 계정, Ollama, 외부 서버와 무관합니다.

저장 데이터는 모의 세션을 구분하는 임시 무작위 식별자(32자리 16진수), 처리 성공 순번, 닉네임, 입력 채팅, 모의 답변 텍스트뿐입니다. 사용자 PC 운영체제·CPU·RAM·GPU·설치 목록·계정·실행 시각을 자동 기록하지 않습니다. **실패한 입력, 아직 대기 중인 채팅은 저장하지 않습니다.** 동일한 채팅이 여러 번 성공하면 서로 다른 순번으로 보존합니다. 같은 세션·순번을 다시 저장할 때는 동일한 내용만 중복 방지하며, 기존 내용이 달라졌으면 전체 저장을 취소합니다. 세션을 초기화하면 새로운 세션 식별자를 사용하므로 이전 저장 내역을 덮어쓰지 않습니다.

기본 저장 경로는 Windows의 `%LOCALAPPDATA%/AISTING/core_response_records.sqlite3`입니다. 이 경로는 기존 `conversation.sqlite3`(채팅 연습 기억) 및 `settings.json`과 **서로 다른 파일**입니다. 임의의 다른 SQLite/일반 파일을 덮어쓰지 않도록 DB 식별값과 테이블 구조를 검사하고, 기존 파일/링크/정션을 보호합니다. SQLite 매개변수 바인딩, 원자적 트랜잭션 및 실패 시 롤백을 사용합니다. 1회 저장은 현재 모의 코어의 메모리 이력 최대 500건으로 제한됩니다. 오래된 이력은 코어의 기존 500건 상한에 따라 메모리에서 제외되므로 **저장 전에 오래된 성공 응답이 누락될 수 있습니다.** DB 전체는 최대 10,000건이며 자동 정리·삭제는 하지 않습니다.

`저장 후보 미리보기`는 메모리에서 최대 5건의 짧은 내용을 표시합니다. `저장 기록 30건 조회` 버튼을 눌러야 DB를 읽으며, 없으면 파일을 생성하지 않습니다. `전체 기록 삭제`는 두 번의 확인을 받은 경우에만 **이 전용 DB의 응답 행만** 지우고, 다른 설정/기억/대기열/모의 이력은 변경하지 않습니다. DB 파일 자체와 테이블 구조는 유지합니다. 삭제한 기록은 앱에서 복구할 수 없으므로 주의해야 합니다.

## 정확한 한계와 승인 상태

모의 코어의 **수동 스냅샷 저장**이지 실제 AI 모델 생성 기록 자동 저장, 실제 방송 채팅 아카이브, 장기 기억 검색, 자동 백업, 사용자 PC 실행 검증이 아닙니다. 저장된 내용은 사용자 개인 대화가 될 수 있으므로 운영자 확인을 필수로 합니다. 실제 Windows 실기기/EXE 테스트, 10단계 최종 승인 및 11단계 이후 사용자 PC 확인은 **pending**, 공식 진행률 **9/100**을 유지합니다.

## 재현

- 자동 회귀: `python -m unittest discover -s tests -q`
- 가상 Tk GUI: `xvfb-run -a python scripts/gui_response_records_smoke.py`
- Windows 수동 확인(사용자 승인 후): 이미 준비된 Python으로 `scripts/run_desktop.py` 실행 → `기본 코어 수동 실행`에서 대본 추가·모의 실행 → `응답 기록 저장`에서 미리보기 → 명시적 확인 후 저장·조회.

테스트는 임시 폴더의 가상 SQLite 파일만 사용합니다. 기존 사용자 PC 파일을 읽거나 수정하지 않습니다.
