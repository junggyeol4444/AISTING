# 25단계 — 한국어 대화 구조 시험 (오프라인 모의 응답)

## 실제 구현

`src/ai_broadcaster/korean_dialogue_test.py`는 기존 22단계 `OfflineCoreSession`을 **시험마다 새로** 만들고, 기존 `MockCoreReplyPort`만 사용합니다. 기본 예시 7건은 인사·질문·중복 입력·게임 이모지·혼합 한국어/영어/숫자·문장부호를 포함합니다. `한국어 대화 시험` GUI에서 예시를 직접 수정하고 **수동 실행**할 수 있습니다. 입력은 `닉네임: 채팅` 형식으로 최대 30건·10,000자입니다.

- 검사: 실제 처리한 입력의 FIFO 순서/닉네임/원문 일치, 중복 보존, 한글이 포함된 비어 있지 않은 응답, Unicode 대체 문자 및 잘못된 제어 문자 검출.
- 결과: 건별 응답/실패 사유와 통과 수/전체 수, 미처리 수, 중단 오류를 화면에 표시. 일부 성공 후 오류가 나면 전체 성공으로 보고하지 않음.
- 부작용 차단: 시험 코어는 기존 코어 세션·채팅 연습·SQLite 기억과 독립이며, 사용자 선택값을 검증만 합니다. 기존 방송 설정/사용자 파일을 저장하지 않습니다. 실제 Ollama를 선택한 상태에서도 연결하지 않습니다. 외부 API/계정/프로세스/OBS/방송·PC 사양 조회 없음.
- 입력을 바꾸면 새로운 독립 모의 세션으로 재시험합니다. 예시 재설정 버튼은 텍스트만 바꾸며 파일에 저장하지 않습니다.

## 이 시험으로 **확인하지 못한 것**

모의 응답기는 입력을 인용하는 정해진 문구이므로 한국어 **자연스러움·의미 이해·맥락 기억·모델의 실제 한국어 생성 성능**을 측정할 수 없습니다. 위 구조 시험 통과를 한국어 AI 품질 검증 완료로 해석하지 않습니다. 실제 로컬 Ollama 모델의 한국어 응답 시험은 사용자 PC에서 명시적 승인 및 모델 준비 후 별도로 수행해야 합니다. 26단계 대화 맥락 유지 검증도 후속 작업입니다.

10단계 전체 개발 기준 최종 승인과 11단계 이후 사용자 PC 실확인은 계속 `pending`입니다. 공식 9/100을 유지하며 Windows EXE/실기기 실행은 미검증입니다.

## 재현 방법

- 자동: `python -m unittest discover -s tests -q`
- Linux 가상 화면: `xvfb-run -a python scripts/gui_korean_dialogue_test_smoke.py`
- Windows Tkinter: 이미 설치된 Python으로 `scripts/run_desktop.py` 실행 후 `화면 이동 → 한국어 대화 시험` 탭에서 수동 실행. 실제 PC 검증은 사용자 승인 전 자동 실행하지 않습니다.

`tests/test_korean_dialogue_test.py`는 정상/실패/문자 깨짐/순서/중복/30건 상한/설정 불변/무접속/예외 시 미처리 보존을 검사합니다.
