# 기획안 요구사항 기준서 (1단계 산출물)

기준: 사용자가 제공한 `ORIGINAL_PLAN.txt` 1~8부. 외부 자료나 새로운 행동 규칙을 임의 추가하지 않는다.

## 목적
- 운영자는 장기간에 걸쳐 유지보수만 하는 수준을 목표로 AI 방송인을 구축한다.
- AI 방송인은 채팅·음성·아바타·방송 시작/진행/종료·공지·기억의 결합 시스템이다.
- 단, 무사고 완전 무인 운영을 보장하는 목표로 해석하지 않는다.

## 운영자가 결정하는 원칙
- 사람처럼 자연스러운지 판단하는 권한은 운영자에게 있다.
- 채팅은 **기본적으로 다 읽고 다 반응**한다. 의도적인 일부 누락을 기본으로 하지 않는다.
- **인위적인 응답 지연을 기본으로 추가하지 않는다.** 대화 맥락에 따라 빠르게 반응한다.
- 말투와 성격은 운영자가 정하는 페르소나로 설정한다.
- 수정은 운영자가 관찰해 피드백하면 반영하는 방식으로 진행한다.

## 기능 구획
1. LLM와 페르소나: 대사 생성, 캐릭터 일관성.
2. TTS: 한국어 음성, 사용 권한이 있는 목소리.
3. 아바타: Live2D/VRM 중 선택, 음성과 립싱크.
4. 입력: 라이브 채팅 수집, 나중에 선택적으로 게임 화면 인식.
5. 방송 운용: OBS 송출 시작·종료, 스케줄러, 자연스러운 마무리.
6. 공지: 디스코드·카페 등 운영자 선택 채널 공지.
7. 기억/운영: 방송 로그, 장기기억, 자동 재시작·비용 점검.

## 승인 전 보류하는 의사결정
- 방송 플랫폼·방송 콘셉트·캐릭터·아바타 종류는 **프로그램 내부에서 선택 및 변경**하도록 이미 지시됨.
  사용 전 특정 선택지를 확정하라는 요구는 하지 않음. 운영 방식은 무료·로컬 PC로 확정됨.
- 목소리 자료의 실제 권리·동의, 모델 및 프로그램 설치, 플랫폼 계정 인증 등
  외부 실행에 영향을 주는 별도 결정은 명시적 사용자 승인을 기다림.
- 외부 서비스 인증, 결제, 프로그램 설치, 실제 방송 및 외부 게시.

## 개발 순서
- 수동 핵심 기능 → 수동 송출 확인 → 자동 종료 → 자동 시작 → 자동 공지 → 운영 안정화.
- 게임은 원 기획안에 따라 기본 완성 이후 선택적 확장으로 둔다.
- 하나의 단계가 테스트를 통과하지 못하면 완료 표시를 하지 않는다.
- 기술 검증을 통과한 단계는 운영자가 이 대화에서 개발을 지시했을 때 이어간다. 예약 또는 주기적 자동 개발은 실행하지 않는다. 운영자 결정이 필요한 사항은 승인까지 보류한다.

## 1단계 검증 기준
1. 사용자가 제공한 원본 기획안이 파일에 포함되어 있다.
2. 100단계 로드맵이 정확히 100개이며 번호가 연속된다.
3. 핵심 기본값(채팅 전체 반응, 인위적 딜레이 없음, 운영자 판단)이 구조화된 설정에 포함된다.
4. 프로그램 설치/결제/게시/방송은 운영자 승인 전 기본 비활성이다.

**상태:** 기술적 산출물 작성 및 자동 테스트 통과. 1단계 완료. 운영자 결정 항목은 계속 보류.

## 로컬 단독 개발 정책 업데이트

사용자 지정: 집 PC, 무료만 사용. 방송 플랫폼/콘텐츠/캐릭터·목소리·아바타는 프로그램에서 선택.
소스 개발은 이 채팅에서 ZIP으로 전달하며 외부 소스관리 자동화를 사용하지 않음.
AISTING 앱 자체의 예약 실행은 기본 비활성으로 유지하되, 사용자가 이 대화에서 명시적으로 요청한 주기적 개발 예약은 앱 자체 실행 예약과 구분함.
