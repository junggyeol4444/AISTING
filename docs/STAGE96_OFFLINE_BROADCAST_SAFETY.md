# v96 / 원본 095 — 방송 중 이상 상황 감지 및 안전 제어 (오프라인 부분 구현)

## 원본 의도 및 승인·검증 경계
원본 095 `방송 중 이상 상황 감지 및 안전 제어`는 **실제 방송 상태, 부적절 발언 또는 장애 발생 시 운영자가 위험을 감지하고 개입할 수 있는 체계**가 목표다. 이 ZIP은 **실제 방송 상태 수집, OBS 정지, TTS 음소거, 실시간 AI 응답 차단, 자동 방송 강제 종료, 사용자 PC 감시는 구현하지 않았다.** 네트워크, OBS, 모델, 장치, 파일 수집, 백그라운드 스케줄링 및 음성 자료 접근이 없다.

## 실제 변경 범위
- `src/ai_broadcaster/offline_broadcast_safety.py`: 기존 061 가상 연결, 062 수신 기록, 063 FIFO, 065 모의 응답을 **읽기 전용**으로 점검하는 `OfflineBroadcastSafetyGate` 추가. 별도 메시지 큐/AI 응답/플랫폼 수신 기능을 중복 구현하지 않는다.
- 운영자가 수동으로 넣은 **가상 초** 기준에서 정체 시간(기본 120초), 모의 메시지 대기열(기본 50건) 초과, 모의 연결 해제/세션 교체, 중단된 FIFO/답변, 수신·응답·순번·처리 커서 손상, 가상 시간 역행, 운영자 **수동 사고 제보**를 감지한다.
- 어떤 이상이 감지되면 `held=True`로 **감시기 내부에만 보류 판정**을 유지한다. 이상이 사라져도 자동 해제하지 않으며, 안전함을 재검사한 후 운영자가 명시적으로 `manual_acknowledge()` 할 때만 해제한다. 가상 연결 세션을 교체한 경우에는 기존 감시기 해제를 거부한다.
- `SafetyDecision`은 immutable이며 사용자 채팅 원문·닉네임·오류 세부값을 결과 문자열에 넣지 않는다. 임의 채팅 선별/삭제·자동 재시도·인위적 지연이 없다.
- GUI `방송 이상 감지·안전 제어 모의` 탭의 **수동 검사 버튼**은 실제 사용자 수신함이나 현재 진행 세션을 가져오지 않고 독립 가상 모의 6개 상황(정상, 정체, 보류 유지, 수동 해제, 연결 해제, 기록 손상)을 시험한다. 화면의 보류는 실제 방송/실제 장치의 제어가 아니다.
