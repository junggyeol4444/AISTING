# AISTING Windows EXE — OBS 읽기 전용 연결과 아바타 별도 창

AISTING의 최종 출력은 **Windows EXE 프로그램**이며, 이번 구현은
사용자 승인 없이 실제 방송을 시작하지 않는 OBS 연동 기초다.

## 이번에 구현
- '2D 아바타' 탭에서 **아바타 별도 창 열기**로 독립 OS 창 생성.
- OBS에서 사용자가 직접 '창 캡처' 소스로 이 창을 선택할 수 있도록 함.
  OBS 설정·장면 등록·송출을 프로그램에서 자동 수행하지 않음.
- 'OBS 연결 확인' 탭에 로컬 포트(기본 4455), 비밀번호 입력 및
  **OBS 연결 상태 확인** 버튼 추가.
- OBS Studio 내장 WebSocket v5 프로토콜을 Python 표준 라이브러리로 처리.
- TCP 목적지는 **127.0.0.1**로 고정; 외부 서버/계정 없음.
- 읽기 전용 요청은 **GetVersion**, **GetSceneList**, **GetStreamStatus** 단 세 가지.
- 현재 OBS 버전, 장면 이름 목록, 송출 켜짐 여부를 표시하되 변경하지 않음.
- OBS WebSocket 인증 challenge + salt, 비밀번호는 앱 설정 파일에 저장하지 않음.
- 사용자 버튼을 누른 뒤에만 접속하고, 불통/암호 오류에는 안내 표시.
- Windows EXE 빌드 및 가짜 WebSocket 서버를 사용한 테스트 포함.

## OBS가 이미 PC에 있는 경우 (선택사항)
1. OBS Studio를 실행하고 OBS의 WebSocket 서버가 로컬에서 사용 가능한지 확인.
2. AISTING.exe의 'OBS 연결 확인' 탭에서 포트와 비밀번호 입력 후 확인.
3. 아바타를 보여주려면 '2D 아바타'에서 '별도 창 열기'를 누르고
   **OBS 안에서 본인이 창 캡처 소스를 선택**해야 함.

## 한계/안전
- 이 작업은 **자동 방송 송출·종료·OBS 장면 생성·전환 기능이 아님**.
- 사용자의 PC에 OBS가 없으면 자동 설치하지 않음.
- OBS 설정·장면 연결은 운영자가 직접 해야 하고, PC에서 실사용 확인 필요.
- 샘플 캐릭터 입 움직임은 음소 인식이 아닌 오디오 재생 상태 기반.
- 개인 비밀번호/방송 키/API 키는 GitHub에 올리지 않음.
- 유료 프로그램·외부 API·예약 개발 실행 없음.

## 새 기능: 장면별 소스 확인 (읽기 전용)

'OBS 연결 확인'에서 장면 목록을 불러온 후 장면 하나를 선택하고 **선택 장면 소스 확인**을 누르면
OBS WebSocket v5의 `GetSceneItemList`로 해당 장면의 소스 이름·종류·사용 여부를 읽습니다.
소스의 활성화 상태는 읽을 뿐 변경하지 않으며, 네트워크 접속은 운영자가 버튼을 눌렀을 때만 합니다.

- `window_capture` 소스 중 이름에 AISTING이 들어가면 **캡처 후보**라고만 표시합니다.
- 이름이 다른 창 캡처가 있으면 캡처 대상은 확인되지 않았다고 표시합니다.
- 소스가 없다면 OBS에서 운영자가 직접 추가해야 한다고 안내합니다.
- 이름이나 소스 종류만으로는 실제 캡처 대상 창·검은 화면·출력 품질을 확인할 수 없으므로 **실제 캡처 성공이나 방송 준비 완료 판정은 하지 않습니다**.
- 실행 전 OBS 설치/웹소켓 활성화/암호 설정 여부는 운영자가 직접 확인해야 합니다.
- 모든 요청은 GetVersion/GetSceneList/GetStreamStatus/GetSceneItemList 네 가지 읽기 전용입니다.

최종 EXE는 Windows 프로그램이며 예약 작업은 꺼져 있습니다.
