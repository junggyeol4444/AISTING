# 27단계 — 기본 응답 오류 처리 (오프라인 모의 코어)

## 실제 구현

기존 `OfflineCoreSession`의 채팅 FIFO, 중복 입력, 최대 500건 대기열·이력, 최대 50건 배치, 최근 8건 맥락 전달을 유지하면서 **오류 분류와 명시적 복구**를 추가했습니다. 답변 포트의 시간 초과(`timeout`), 연결 예외(`connection`), 일반 생성 예외(`generation`), 문자열이 아닌 응답(`invalid_type`), 공백 응답(`empty_reply`), 6,000자 초과 응답(`oversized_reply`)를 구분합니다. 외부 포트의 예외 원문(민감 정보가 포함될 수 있음)은 사용자 메시지에 표시하지 않고 고정된 안전 문구로 바꿉니다.

오류가 나면 **실패한 선두 입력을 대기열에서 제거하지 않고**, 앞서 성공한 이력도 유지합니다. `last_failure`에 실패 코드·시도 횟수·실패 입력을 메모리로 보관합니다. **자동 재시도는 없으며**, 최초 시도 1회와 사용자 수동 재시도 최대 2회(총 3회)까지만 허용합니다. 3회 이후에는 해당 입력에 대한 추가 포트 호출을 차단합니다. 수동 제외는 `discard_failed(confirmed=True)`로 명시적으로 요청해야 하며, GUI에서는 **별도 확인 대화상자**에서 승인한 경우에만 실패한 선두 입력 1건을 제외합니다. 다른 대기 입력과 성공한 이력은 유지됩니다. 세션 초기화는 기존과 같이 모의 세션만 초기화합니다.

기존 `기본 코어 수동 실행` 탭에 **실패 건 수동 재시도 / 실패 건 제외(별도 확인)** 버튼과 오류 코드·시도 횟수 표시를 추가했습니다. `응답 오류 처리 시험` 탭에서는 사용자가 버튼을 누른 경우에만 별도 모의 포트로 8개 시나리오를 검증합니다: 시간 초과, 연결 예외, 생성 예외, 응답 타입 오류, 공백, 과대 길이, 재시도 상한/확인 후 제외, 일부 성공 뒤 오류/복구. 기존 기본 코어 세션, 설정 파일, SQLite 기억은 이 시험에서 읽거나 변경하지 않습니다.

## 정확한 검증 범위

이 기능은 **로컬 메모리 내 모의 답변 포트**의 실패 처리입니다. 실제 Ollama 생성 API와의 재연결/네트워크 타임아웃, 실제 방송 중 장애 대응, 지속적 실패 로그 파일 저장, 자동 장애 복구, 장기 기억 복원, 응답 기록 저장(28단계)은 아직 구현·검증하지 않았습니다. 특히 24단계의 **사용자 승인 후 로컬 모델 목록 조회** 기능은 변경하지 않았으며, 개발 테스트에서는 그 조회를 실행하지 않았습니다.

실제 Windows PC 정보·설치 상태는 조회하지 않았고 Windows EXE/실기기 테스트는 승인 대기입니다. 공식 진행률 **9/100**, 10단계 최종 사용자 승인과 11단계 이후 실제 PC 확인은 `pending`입니다. 사용자가 프로그램에서 플랫폼·콘텐츠·캐릭터·목소리·아바타를 자유롭게 선택/변경하는 기존 기능을 유지합니다.

## 재현

- 자동 회귀: `python -m unittest discover -s tests -q`
- GUI (Linux 가상 화면): `xvfb-run -a python scripts/gui_response_error_smoke.py`
- Windows GUI (사용자 PC 승인 후): 이미 설치된 Python/Tkinter로 `scripts/run_desktop.py` 실행 → 상단 `화면 이동`에서 `응답 오류 처리 시험` 선택. 이 단계에서 PC 실기기 검증을 수행했다고 간주하지 않습니다.

신규 테스트는 실패 코드, 입력 보존, 중복 FIFO, 안전한 오류 메시지, 시도 상한, 사용자 확인 없는 제외 차단, 부분 배치 복구, 선택값 보존, 기존 설정 불변, 네트워크/SQLite/프로세스/PC 조회 금지를 검사합니다.
