# v95 / 원본 094 — 프로그램 오류 자동 복구 (오프라인 *부분* 구현)

## 원본 의도와 이번 구현 범위
원본 계획 `094 프로그램 오류 자동 복구`는 실제 방송 프로그램 오류 발생 시 자동 복구를 목표로 한다. 이 개발본은 **실제 Windows 프로세스, OBS 송출, TTS/음성 엔진, AI 모델, 플랫폼/서버 연결을 재시작하거나 복구하는 기능을 포함하지 않는다.** 원본 094는 아직 `pending`이다.

기존 단계 062 수동 모의 채팅 수신함, 063 FIFO 순서 관리, 065 모의 응답기를 재사용해, 응답 생성 오류 시 **정해진 복구 가능 상태에서만 오류 차단 플래그를 자동 해제**하는 작은 `OfflineProgramRecovery` 감독기를 구현했다.

- 정상 처리: 운영자가 호출한 모의 메시지 **1건만** 답변한다.
- 허용된 복구: 065단계의 `reply_next`에서 `ValueError` 및 응답 중단 상태가 발생한 뒤, 수신 기록·순서 기록·대기 중 채팅·기존 응답·가상 연결 상태가 모두 변경 없이 보존된 경우에만 `resume()`을 **한 번** 호출해 *처리 상태만* 복원한다.
- 자동 답변 재실행은 절대 하지 않는다. 실패한 FIFO head는 동일 순번으로 보존되며, 다음 작업 처리에는 별도 `process_one()` 호출이 필요하다. GUI의 단일 **감사 버튼**은 안전성 확인을 위한 격리된 모의 객체에 대해 이 별도 호출까지 순서대로 실행하는 시험이며, 실제 사용자 채팅 처리 버튼/자동 복구 운영 기능이 아니다. 임의 채팅 건너뛰기, 내용 선별, 인위적인 지연은 없다.
- 수신 기록 변경, 신규 수신 삽입, 가상 연결 변경/해제, 응답 기록·순서 기록 변조, 임의 오류, 복원 실패는 **검역(`RecoveryDenied`)**으로 차단한다. 오류 이유나 모의 문구/닉네임을 영속 로그에 남기지 않는다.
- GUI `프로그램 오류 복구 모의 감사` 버튼은 **기존 사용자 세션과 분리된 독립 모의 3건**만 사용하여 정상 첫 답변 → 가상 오류 → 자동 상태 복원(미처리 메시지 보존) → 운영자 수동 다음 처리 2건을 확인한다. 실제 사용자의 채팅이나 기록을 읽지 않는다.
- 소켓 연결, 파일 스캔/저장, 앱/OS 프로세스 실행, OBS 호출, 자동 예약, 계정 입력, 음성/PC 정보 수집 **없음**.
