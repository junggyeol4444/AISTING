# AISTING 누적 v40 · 원본 039 운영자 피드백 수정 기능 준비

## 기획안 및 로드맵 근거

- 원본 기획안 1-2, 3-2, 3-5: 무엇이 자연스러운지는 운영자가 결정하며, 먼저 AI가 추측하여 규칙을 강제하지 않는다. 운영자가 보고 문제를 알려주면 그 뒤 수정한다.
- `docs/ROADMAP_100.md`의 원본 039 '운영자 피드백 수정 기능 준비'를 이번에 진행. 누적 ZIP 번호 v40은 로드맵 040 완료의 뜻이 아니다.
- 원본 기획안 3부의 이름·성격·말투, 금기·대응 방향을 현재 설정 상태 그대로 보존한다.

## 실제로 만든 기능

- `src/ai_broadcaster/operator_feedback.py`: 순수 로컬 수동 요청 장부. `말투 / 성격·취향 / 채팅 반응 / 자발적 발화 / 기타` 중 사용자가 선택한 분류와 관찰 사실, 요청한 수정 방향을 보존한다. 사용자 입력하지 않은 문제/수정은 생성하지 않는다.
- 입력 필수, 항목별 최대 500자, 순번 고유·상승 유지, 저장 항목 최대 40개, UTF-8 JSON 파일 최대 65536바이트. 내용 손상·형식 오염·링크/정션·과다 크기는 실패 처리하고 기존 파일을 덮어쓰지 않는다.
- 화면 `운영자 피드백 수정 준비`: 미리보기(파일 읽기·쓰기 없음), **1회 확인 후 추가**, 특정 순번 지정 **1회 확인 후 수정**, **수동 목록 불러오기**, 특정 순번 **2회 확인 후 삭제**.
- 실제 저장 위치는 `LOCALAPPDATA/AISTING/operator_feedback_requests.json` (Windows), 그 외 플랫폼에서는 `~/.aisting/operator_feedback_requests.json`. 앱을 열었다고 자동으로 이 파일을 읽거나 만들지 않는다.
- 저장/수정은 원자적 임시 파일 → 파일 교체로 처리한다. 기존 `settings.json`, 캐릭터 선택, 원본 기획안, SQLite 기억, 음성·아바타, 방송 제어, 사용자 승인 파일은 변경하지 않는다.

## 강제하지 않는 정책과 검증 범위

- **요청 내용 저장은 캐릭터·프롬프트·LLM 답변에 적용하는 것이 아니다.** 저장된 내용을 자동으로 로드해 방송인 행동을 변경하거나 자연스러움이 개선됐다고 합격 판정하지 않는다. 실제 사용자의 수정 승인, 실제 로컬 AI 품질 평가 및 방송 통합은 후속 검증 대상으로 남긴다.
- PC 정보 자동 수집·원격 접속, 실제 LLM/OBS/방송, GitHub/클라우드/유료 API, 계정 연결·설치·결제는 수행하지 않는다.
- 10단계 전체 개발 기준 최종 승인, 11단계 이후 실기기 정보 확인, Windows 실기기 및 EXE 검증은 사용자 대기로 남겨둔다. 개발된 코드 진행 범위와 승인 완료 범위는 분리해 보고한다.

## 실제 확인

- `tests/test_operator_feedback.py`: 12개 테스트(검증, 승인 게이트, 저장·변경·삭제, 순번/중복 방지, 보존, 상한, 훼손, 링크 차단, 네트워크/서브프로세스 접근 차단).
- `scripts/gui_operator_feedback_smoke.py`: Linux Xvfb에서 화면 이동, 잘못된 입력, 미리보기 부작용 없음, 취소, 추가, 수동 조회, 수정 취소/적용, 삭제 중간 취소/최종 수행을 시험.
- 전체 자동 테스트, GUI 회귀, Python 구문 검사, 최종 압축 재검증은 `logs/STAGE40_FINAL_VALIDATION.txt` 참고.

## 로컬에서 재현하는 방법 (외부 서비스 불필요)

```sh
PYTHONPATH=src python -m unittest discover -s tests -q
PYTHONPATH=src xvfb-run -a python scripts/gui_operator_feedback_smoke.py
```

위 두 번째 명령은 Linux 가상 화면 예시이며 Windows 실기기 테스트 결과가 아니다.
