## 이번 204절 실제 제품 소스 개발
1. **새 `src/ai_broadcaster/long_term_conversation_memory.py`**: 기존 `ConversationMemory`의 실제 대화 `exchanges`와 **독립된 로컬 SQLite 장기 기억 보관소**를 구현했다. 새 보관소는 `application_id`·정확한 테이블 스키마·일반 파일/심볼릭 링크 검사를 수행하며, 사용자 선택 시에만 만들어진다. 기존 캐릭터/모델/대화 SQLite 스키마를 수정하지 않는다.
2. **장기 기록 원자성**: 기존 원본 대화 INSERT + 장기 SQLite INSERT + 원래 최근 5000건 정리를 `ATTACH DATABASE`와 **동일 SQLite 트랜잭션**에 묶었다. 새 보관을 처음 켜면 아직 원본에 남아 있는 최대 5000건을 `origin_id` 중복 방지 키로 한 번 복사한다. 과거에 이미 원본에서 삭제된 대화는 복원했다고 주장하지 않는다. 장기 보관소에는 자동 만료/임의 삭제를 넣지 않았으므로 디스크 사용량이 증가할 수 있다.
3. **장기 과거 검색**: 현재 질문의 실제 단어를 이용해 별도 서버·임베딩·모델 없이 장기 SQLite **전체 누적 대화**를 검색한다. 원래 최근 8개 문맥을 제외하고 가장 관련 높은 과거 최대 2개를 실제 과거 순서로 모델에 제공한다. 4개 이내 결과만 메모리에 유지하고 실제 기록이 없으면 허구를 만들지 않는다. 검색/발화 1~3초를 보증하지 않는다.
4. **기존 `desktop_chat.py`**: 수동 로컬 Ollama와 4플랫폼 직렬 `LocalChatRunner`에 별도 `long_term_memory` 선택값을 전달하여 기존 `LocalOllamaReplyGenerator`의 기억 저장/관련 문맥 경로를 재사용한다. 원래 모델·96토큰·keep_alive·캐릭터·FIFO 순서를 변경하지 않는다.
5. **기존 `ordered_parallel_local_ai.py`**: 최대 4개 선행 모델 추론에서도 **실제 FIFO 확정 시점**에만 같은 장기 기억 원자 저장을 실행한다. 미완료 미래 응답을 확정 기억으로 저장하지 않는다.
6. **기존 `desktop_chat_tab.py`**: Windows Tk GUI에 기본 꺼짐인 `장기 보관` 체크박스, 최근/장기 개수 표시, 수동·4플랫폼 직렬·병렬 모드 전달, 기존 기억 전체 삭제 버튼에서 장기 DB가 있으면 **운영자 재확인 후 양쪽을 함께 삭제**하는 기능을 연결했다. 공식 Live2D 서버의 독립 기억 설정에는 적용되지 않으며 이를 별도로 알린다. 다른 계정·채팅·OBS 방송·녹화/공지 발신은 하지 않는다.
