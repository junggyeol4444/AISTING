# 누적 개발본 v38 · 원본 로드맵 037 채팅 전체 반응 원칙 적용

## 기획안 기준과 실제 구현 범위

원본 `docs/ORIGINAL_PLAN.txt` 1-2, 3-2, 4-2는 **모든 채팅에 반응하고 인위적인 기다림·사전 선별을 넣지 않는다**고 정하며, 실제 자연스러움의 평가는 운영자에게 남긴다. `config/roadmap.json` 원본 037의 명칭은 **채팅 전체 반응 원칙 적용**이다.

v36의 원본 035 기본 대화 반응 검사는 독립된 단발 대본 검증이었고, v37의 원본 036은 처리 시간의 수동 관찰이었다. **이번 기능은 단발 시험을 다시 만드는 것이 아니라, 별도 메모리 모의 세션의 채팅을 여러 번 접수하고 순차 처리하는 과정에서 전건 반응 정책을 실행하는 것**이다.

## 실제 변경사항

- `src/ai_broadcaster/all_chat_policy.py`: `AllChatPolicySession`. 사용자가 입력한 채팅은 접수 순서에 따라 고유 순번을 받고 동일 내용/발신자를 중복 제거하지 않는다. 여러 차례 접수, 다음 1건, 최대 50건 처리, 전체 누적 500건까지 감사한다. 접수와 처리 동작이 분리되어, 접수만으로 답변을 만들지 않는다. 각 접수·응답·미처리 원문을 감사 표시에 반영한다.
- 모의 응답 실패 시 실패한 선두 채팅 및 이후 대기 입력을 보존하고, 실패 후 추가 버튼으로도 암묵적 재시도는 하지 않는다. 재시도는 **사용자 전용 버튼**으로 1회씩 진행, 코어의 시도 횟수 제한(총 3번) 유지. 실패 제거/채팅 생략 UI를 추가하지 않는다. 모델 오류 원문은 UI에 노출하지 않는다.
- `src/ai_broadcaster/desktop.py`: `전체 채팅 반응 원칙` 탭. 수동 접수·다음 1건·최대 50건·실패 건 수동 재시도·확인 후 **해당 임시 모의 세션만** 초기화. 사용자 플랫폼/콘텐츠/캐릭터/목소리/아바타 선택은 기존 인터페이스에서 유지.
- `tests/test_all_chat_policy.py`: 12개 자동 테스트. FIFO, 중복, 다회 접수와 연속 처리, 실패 정지/명시적 복구/재시도 제한, 총량 상한, 원자적 입력 검사, 민감 예외 비노출, 선택값 불변, 네트워크·SQLite·대기·프로세스·PC 조사 없음.
- `scripts/gui_all_chat_policy_smoke.py`: Linux Xvfb에서 GUI 이동/수동 접수/1건 처리/잔여 전건 처리/중복 유지/잘못된 입력/초기화 취소 및 확인을 검사.

## 명확히 완료하지 않은 사항

- **실제 스트리밍 플랫폼 채팅 수집, Windows 사용자 PC에서의 실제 응답, 로컬 AI 모델 자연스러움, 사용자의 체감 판단**은 검증하지 않았다.
- 사용자가 별도 요청하지 않는 한 설정·SQLite 기억·금기 파일 변경, PC OS/CPU/GPU 조회, 외부 서버 연결, OBS 제어, 예약 실행, 설치, 계정 연결을 하지 않는다.
- 오류로 선두가 대기할 때 뒤의 채팅도 순차 처리가 중지된다. 이 경우 **모든 채팅에 답했다는 완료 판정을 절대 하지 않는다**. 의도적인 무시가 아니라 누락을 방지하는 보존 정책이다. 장기 장애/대량 트래픽 처리 정책은 사용자 평가 후 향후 단계에서 별도 결정한다.
- 단계 010 최종 개발 기준 사용자 승인, 011 이후 사용자 PC 확인, Windows EXE/실기기 검증은 pending 유지. 로드맵 번호 037의 **오프라인 구현 범위만** 확인되었다.

## 검증 명령

```sh
PYTHONPATH=src python -m unittest discover -s tests -q
PYTHONPATH=src xvfb-run -a python scripts/gui_all_chat_policy_smoke.py
```

테스트 숫자와 보존 비교/ZIP 재검증은 `logs/STAGE38_FINAL_VALIDATION.txt` 및 `TEST_RESULTS.txt`에 기록한다.
