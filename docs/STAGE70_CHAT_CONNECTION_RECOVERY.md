# AISTING v70 / 원본 069 채팅 연결 장애 복구 테스트 — 오프라인 모의

## 검토 기준

`docs/ORIGINAL_PLAN.txt`의 전체 채팅 반응, 기본 고의 지연 없음, 운영자 판단 우선 원칙과 `docs/ROADMAP_100.md` 069, `config/roadmap.json`의 `pending`을 보존합니다. v69의 061 가상 플랫폼 연결, 062 수동 채팅 수신함, 063 FIFO 순서, 065 모의 응답, 068 여러 시청자 흐름을 **새 큐/새 수신기 없이 그대로 재사용**합니다.

## 수동 모의 흐름

1. 방송 설정에서 플랫폼(0~3개) 선택. 061 탭에서 **가상 연결 시작**. 062 탭에서 **가상 수신 준비** 후 가상 채팅을 직접 접수합니다. 필요하면 063/065에서 순서 동기화 및 일부 응답을 실행합니다.
2. `채팅 연결 장애 복구 모의` 탭에서 **모의 장애 발생**을 누르면 기존 061 연결을 해제하고 062 수신 바인딩을 해제합니다. 이미 접수된 채팅, FIFO 순서, 모의 응답 이력은 삭제하지 않습니다. 새 수신은 거부합니다.
3. **재연결 실패 1회 시험**은 선택 플랫폼 하나의 가상 핸드셰이크를 한 번 실패시킵니다. 자동 재시도·자동 재준비는 없습니다. 연결 시도 횟수와 실패 횟수만 메모리에 표시합니다.
4. **수동 가상 재연결**을 누르면 061의 기존 동일 세션에서 수동 연결을 한 번 재시도합니다. 이 단계에서는 아직 062 수신이 재개되지 않습니다.
5. **수신 수동 재준비**를 눌러야 062 바인딩을 다시 설정합니다. 기존 메시지/동기화/응답의 접두 기록과 순번 일치를 검증한 뒤 복구 성공을 표시합니다. 이후 새 가상 채팅 접수와 기존 FIFO 처리가 가능합니다.

## 안전·일관성

- 기존 수신 기록의 순번·내용·길이(기존 접두 부분), 순서 큐와 응답 이력의 이전 접두 기록이 훼손되면 재연결/재준비를 차단합니다. 복구 후 새 채팅이 뒤에 추가되는 것은 정상입니다.
- 플랫폼 선택 변경으로 061 연결 객체가 교체되면 이전 복구 시험은 무효화됩니다. 동일 선택값이라도 새 연결 세션이면 이전 시험을 재사용하지 않습니다.
- 한 세션의 장애 시험은 한 번만 수행합니다. 새 시험은 새로운 수동 연결 세션에서 시작합니다.
- 사용자 설정·기획안·실제 채팅/음성·토큰·계정·사용자 PC 정보는 읽거나 수정하지 않습니다. 네트워크, 백그라운드 재시도, 실제 방송, OBS, 원격 저장소, 클라우드 AI를 호출하지 않습니다.

## 검증 범위와 남은 작업

- 자동 테스트: 장애 전제, 수신 차단, 실패 핸드셰이크, 수동 재연결/재준비, 중복 호출 거부, 메시지/응답 이력 보존, 세션 교체, 변조 방어, 외부 I/O 차단.
- Linux 가상 디스플레이의 Tk GUI 회귀 테스트: 실패→수동 복구→FIFO 응답 완료. Windows 실기기/EXE, 실제 플랫폼 장애·메시지 재전송·누락 복원, 실제 AI/아바타/방송, 자연스러움 평가는 **미검증**입니다.
